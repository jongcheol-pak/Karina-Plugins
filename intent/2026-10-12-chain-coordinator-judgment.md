# Intent: 체인 코디네이터가 사용자 몫 넷 밖의 워커 질문을 스스로 판정한다
Author: 사용자(jongcheol-pak). Status: approved.

## Problem
원문 요청: *"체인으로 실행시 워커탭에서 요청을 하면 코디네이터가 답변을 자동으로 해야 하는데 opus가 능력이 안되는데 모든 답변을 사용자에게 다시 요청해서 자동으로 진행이 안되고 있음. 예로 사용자가 원본하고 동일하게 작업요청을 하면 워커에서 동일하게 기능을 구현할 건지 물어보면 … 무족건 다시 사용자에게 요청함. 심각한 문제로 멈주는게 아니면 사용자가 요청한 내용대로 잘 파악해서 답변을 했서 자동으로 진행 했으면 함. … 규약이 많아서 문제가 되는지도 보고"* → 원인 규명 뒤 *"권장으로 잘 수정해줘 opus 모델이 자동으로 잘 할 수 있게, 추가로 불필요한 규칙 삭제"* · 삭제 범위 질문에 *"chain-plan 전체"* · 후보 라운드에 *"권장"*.

원인(2026-10-11~12 Karina 체인 6계획의 코디네이터 기록 대조): 넘긴 4건 모두 코디네이터가 규약 조항을 들어 넘겼다 — 모델 능력이 아니라 규약 구조다. ① `delegation.md` 가 UX 동작·기존 계약 「변경」·권장안 없음을 전부 사용자 몫으로 돌려 `chain-plan/SKILL.md` 의 "사용자 몫은 넷" 규칙에 다섯째 범주를 더했고 워커는 바로 그 종류(외부 계약·UX)만 묻는다 ② 사용자 원문 답과 코디네이터가 「근거로 정함」으로 채운 재진술 세부를 가르지 않아 코디네이터 자신의 오류 정정이 「목표 변경」이 됐다(plan 3 — 원본대로 agent별 기억 · 약 2시간 정지) ③ 「애매하면 사용자 몫」이 규칙 겹침을 전부 넘김으로 풀었다(plan 6 `(확인 필요)` 승인 · 새 DB 위치).

## Proposed outcome
사용자 몫이 `chain-plan/SKILL.md` 「답하는 기준」 한 곳에 넷으로 정의된다 — ① 실행 시점 승인 항목 ② 사용자가 원문으로 답한 것을 뒤집는 것(그 답에서 온 제약을 넘거나 좁히는 것 포함 · 코디네이터가 근거로 정한 값·제약은 제외 — 다른 설계를 먼저 찾게 한 뒤 판정) ③ 요청 범위 변경(요청 밖 작업 추가 · 계획 간 항목 이동 · 목표 자체 변경) ④ 이미 있는 것을 깨는 변경 중 체인 승인에 명시되지 않은 것(기존 DB 데이터의 목록 밖 쓰기 · 기존 CLI 플래그·설정 키·API 의 이름·인자·기본값 변경·삭제 · 기존 사용자 파일 형식 · 기존 화면 동작). 기준은 「계획에 없던 것인가」가 아니라 「기존 사용자·호출부가 깨지는가」다. 그 밖(새 화면·기능의 UX 갈림길 · 코디네이터 근거 값의 정정 · 새로 만드는 DB 의 위치·이름 · 워커 `(확인 필요)` 내부 설계 · 새 API·설정 추가)은 코디네이터가 사용자 원문·판정 원칙·재진술 목표·워커 권장안으로 판정해 보고에 모은다. 넷 중 하나인지 애매하면 되돌리기 어려운 것만 사용자에게 간다. 체인 승인 화면은 켜고 끄는 「외부 계약 위임」 줄 대신 판정 범위 줄과 계획마다의 판정 원칙(요청·규약에서 읽은 기준 — 예: 원본 이식이면 원본 동작) 줄을 싣고, 판정으로 정한 새 DB 위치·이름은 워커가 DB 목록 안으로 보며, 워커는 판정 원칙에 맞는 선택지를 권장으로 고른다. 위임 장치·워커 외부 계약 표식과, 다른 곳과 겹치는 규칙(`user-relay.md` 실행 시점 승인 · `prior-answers.md` 사용자 몫 앞 답 · `delegation.md` 판정 모음 · `manual-resume.md` 대기 재기동 금지)을 지운다.
