# 사용자에게 넘기기 (`pjc:chain-plan`)

> `../SKILL.md` 「답하는 기준」이 워커의 질문·승인 요청이나 실행 시점 승인 항목을 사용자 몫으로 넘길 때(「사용자에게 넘기기」)와 워커 `plan.md` 승인 요청의 봉투 대조가 어긋날 때(「봉투 밖 승인 요청」)만 이 파일을 연다. 무엇이 사용자 몫인지와 봉투의 세 대조(task 줄·`승인 필요 항목`·`DB 변경`)는 거기가 정본이다.

## 사용자에게 넘기기

- **사용자에게 넘길 때는 사용자를 부른 뒤 묻는다** — 알림이 없으면 사용자는 이 탭에 질문이 떠 있는 줄 모른다. 워커는 답이 올 때까지 상한 없이 기다리므로(`../../plan/references/relay-edge-cases.md`「ask 만료」) 답이 늦어도 따로 알릴 것이 없다.
  1. `PushNotification`(`status: "proactive"`, 메시지 `plan <N>: 사용자 확인 필요 — <질문 한 줄>`) — 지연 로드면 ToolSearch 로 불러 쓰고, 도구가 없거나 보내지 않았다고 하면 건너뛴다
  2. 질문 원문(승인 요청이면 그 승인 제시 전문)과 `GUESS:` 를 그대로 보이고 답을 글자 그대로 옮긴다 — 요약해 넘기면 사용자가 워커의 실제 질문이 아니라 이 세션의 해석에 답하게 된다
  3. `prior-answers.md`「앞선 답」 이 같은 질문으로 고른 앞 답이 있으면 2 에 `참고: plan <M>[ 이어받기 <k>] 에서 같은 질문에 「<답 원문>」(<사용자 답 | 코디네이터 판정>)` 을 덧붙이고, 앞 답과 어긋나게 판정해야 해 넘기는 것이면 ` — 이번에 다르게 볼 이유: <질문에 인용된 새 사실>` 을 잇는다 — 앞 답으로 대신 답하지 않는 대신 사용자가 같은 답을 빨리 고르게 하고, 출처가 없으면 사용자가 코디네이터 판정을 자기 앞 결정으로 읽는다

## 봉투 밖 승인 요청

- **하나라도 어긋나면 봉투 밖이다 — 회피 설계부터 지시한다.** 봉투의 task 줄 대조가 넘침이면 그 task 없이 목표가 되는지 보고 되면 `E: <그 task 를 뺀다> (코디네이터 판정 — <근거>)`, 안 되면 사용자 몫 ③ 요청 범위 변경으로 사용자에게 넘긴다. task 줄 대조가 누락이면 `E: <빠진 항목> 을 넣거나 빠진 근거를 적는다 (코디네이터 판정 — <근거>)`. `승인 필요 항목`·`DB 변경` 대조가 어긋나면 사용자 몫(`../SKILL.md` 넷)이 아닌 한 어긋난 항목이 생기지 않는 설계가 있으면 `E: <회피 설계> (코디네이터 판정 — <근거>)`, 없을 때만 `Y (코디네이터 판정 — <근거>)` — 워커가 스스로 고른 설계가 만든 승인 항목은 대개 다른 설계로 사라진다(`../../plan/SKILL.md` Step 4). 봉투 밖이라는 사실만으로 사용자에게 넘기지 않는다.
