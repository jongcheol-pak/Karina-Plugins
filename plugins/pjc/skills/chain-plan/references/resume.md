# 재개 (`pjc:chain-plan` — 「plan N부터」)

> `../SKILL.md` 「계획 목록」이 「plan N부터」로 불렸을 때만 이 파일을 연다. 재개는 새 Run 을 만들므로 spec `인계:` 의 기본 경로(`docs/plans/chain-<Run id>.md`)는 아직 없는 파일이고, 워커는 그 파일이 없으면 첫 계획으로 넘어간다(`../../plan/references/relay-mode.md`「중계 모드」) — 앞 계획의 결정·제약을 읽지 못한다.

## 재개

- **N 이 1이면 처음 실행과 같다 — 아래를 건너뛴다.**
- **앞 계획들이 쓴 인계 파일을 고른다 — 대상 레포 루트에서 레포 상대 경로로 `grep -lE "^## plan <N-1>([^0-9]|$)" docs/plans/chain-*.md` 를 돌리고, 후보마다 `git log -1 --format='%ct %h' -- <경로>` 의 `%ct` 가 가장 큰 것을 고른다. 커밋이 없는(출력이 빈) 후보는 뺀다** — 한 레포에 여러 체인의 인계 파일이 쌓여 「앞 계획 절이 있는 파일」은 여럿 나온다(Karina 레포 실측 3개). 정규식 끝의 `([^0-9]|$)` 는 `## plan 1` 이 `## plan 10` 에 걸리지 않게 하면서 `## plan 1 이어받기 2` 와 CRLF 줄 끝(`\r`)은 받는다.
- **후보가 없으면 새 Run 경로를 쓰고 아래 줄은 `없음 — 새 파일` 이다.**
- **체인 승인 화면 머리 줄 아래에 `앞 인계: <경로 (근거: 마지막 커밋 <%h>) | 없음 — 새 파일>` 줄을 싣는다** — 다른 체인의 파일을 골랐는지 사용자가 거기서 본다. `E` 로 경로를 고치면 그것을 따른다.
  - 고른 파일에 `## plan <N>([^0-9]|$)` 절이 이미 있으면(멈춘 plan N 이나 그 이어받기가 남긴 것) 같은 줄 끝에 `· plan N 절 이미 있음 — 새 워커가 같은 이름의 절을 덧붙인다` 를 더한다 — 뒤 계획이 두 절 중 어느 것을 따를지 사용자가 미리 안다.
- **spec 의 `인계:` 줄은 Run id 경로 대신 고른 경로를 레포 상대 경로(`docs/plans/…`)로 적은 것이고, 모든 계획 task 에 같다** — 원 서식과 같은 형태라 워커의 Read·커밋 경로가 어긋나지 않고, 워커는 그 파일을 Read 한 뒤 `## plan <N>` 절을 덧붙인다.

## 미병합 병렬 브랜치

> 멈춘 체인에 병렬 그룹(`parallel.md`)이 있었으면, 끝났는데 체인 브랜치에 병합되지 않은 계획 브랜치가 남아 있을 수 있다. 모르고 재개하면 끝난 계획을 처음부터 다시 돌린다.

- **위에서 고른 인계 파일 이름 `docs/plans/chain-<Run id>.md` 에서 옛 Run id 를 얻고, `git branch --no-merged <체인 브랜치> --format='%(refname:short)'` 에서 이름에 `chain-<Run id 앞 8자>-p<M>` 이 든 브랜치를 고른다** — 병렬 워커는 그 이름으로 띄워져(`parallel.md`「띄우기」) 브랜치가 계획 번호를 가진다. 인계 파일을 못 골랐으면 `chain-` 과 `-p<숫자>` 가 든 미병합 브랜치를 전부 후보로 싣고 사용자가 `E` 로 고른다.
- **브랜치마다 `git worktree list --porcelain` 에서 그 worktree 경로를 찾고, 그 경로의 `plan.md` 가 미완료 체크박스(`^- \[ \]`) 0개 · 완료(`^- \[x\]`) 1개 이상이면 완료로 본다** — 마지막 계획은 인계 절을 쓰지 않을 수 있어 인계 절 유무로는 완료가 갈리지 않고, worktree 폴더는 지우지 않으므로 남아 있다(`parallel.md`「닫기」).
- **완료 브랜치는 체인 승인 화면 `앞 인계:` 줄 아래에 `미병합: plan <M> — <브랜치> (완료)` 로 싣고, 승인 뒤 plan N 을 띄우기 전에 `parallel.md`「병합」 으로 먼저 병합한다** — 뒤 계획이 그 커밋을 봐야 한다. M 이 N 이상이면 그 계획은 건너뛴다(이미 끝났다).
- **미완료 브랜치는 병합하지 않고 `미병합: plan <M> — <브랜치> (미완료 — 새로 돌림)` 으로 싣는다** — 그 계획은 체인 브랜치에서 새 워커로 다시 돌고, 옛 브랜치·worktree 경로는 보고의 `병렬 병합:` 줄에 남긴다.
