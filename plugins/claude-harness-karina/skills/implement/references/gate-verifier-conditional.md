# gate-verifier 조건부 상세

> `../../../agents/gate-verifier.md` 에서 떼어 낸 조건부 참조다 — 검증자가 입력에 직전 판정이 있을 때 「직전 판정 재사용」 을, 테스트 명령이 실패했을 때 「실패 재실행」 을, 본문 파일에 `화면 시나리오:` 줄이 있을 때 「화면 시나리오」 를 읽는다. 이 파일의 번호(1번·3번·4번 등)는 그 에이전트 정의 「할 일」 의 번호다.

## 직전 판정 재사용

- **직전 판정 — 입력에 있고 그 `base:` 가 입력의 부모 SHA 와 같으면 `git -C <head worktree> diff --name-only <직전 head>..HEAD` 를 잰다. 전부 `.md`·`.txt` 이고 그중에 `AGENTS.md`·검증 매핑 문서가 없고 매핑이 그 경로에 명령을 걸지 않고, 바뀐 각 파일의 이름이 `.md`·`.txt` 밖 추적 파일에 따옴표 바로 앞 문자열로 나오지 않으면(`local-gate.md`「판정 재사용」 ⓐ 의 `git grep` 그대로 — 빌드가 읽는 문서를 거른다), 직전 `명령:` 에서 exit 0(또는 `재사용`)이던 명령과 직전에 기대대로 동작한 3번 조작·화면 시나리오는 다시 돌리지 않고 `- <명령> → 재사용 <직전 head sha7>` 로 적는다. 직전에 실패한 명령·`늘지 않` 감사·4번 형식 검사는 언제나 돈다. 조건 하나라도 거짓이면 직전 판정을 무시하고 전부 돈다** — 문서만 고친 재검증이 처음부터 빌드하면 바뀌지 않은 코드에 같은 판정을 다시 산다. 재사용한 조작의 스크린샷은 직전 `스크린샷:` 칸의 경로를 옮긴다.

## 실패 재실행

- **6번에서 실패한 명령이 테스트 명령이고 `AGENTS.md` 에 `Test (task)` 줄이 있고 실패 케이스가 10개 이하이면, base 에서는 같은 명령 전체 대신 실패 케이스마다 그 형식(`<대상>` 자리에 케이스 이름)만 돌린다 — base 에서도 실패하면 부모 결함(NOTES)이다. base 에서 통과하면 head 에서도 같은 형식으로 그 케이스만 단독 재실행해, 실패하면 head 에만 있는 실패(FAIL)이고 통과하면 `부하 flaky — <케이스>`(NOTES)다. 단 그 케이스가 1번 바뀐 파일에 정의돼 있으면 flaky 로 치지 않고 FAIL 이다. 조건 하나라도 거짓이거나 빌드가 실패했으면 같은 명령 전체를 base 에서 재실행한다** — 실패 몇 건을 가르려고 base 에서 전체 스위트를 다시 돌면 게이트가 스위트 한 바퀴만큼 늘어난다(Karina 2026-11-13 — 실패 2건에 `cargo test --no-fail-fast` 전체 재실행). 이름 필터 문법은 추측하지 않고 `Test (task)` 형식만 쓴다. 바뀐 파일의 케이스는 이 변경이 공유 상태를 건드려 생긴 간섭과 모양이 같아 flaky 로 넘기지 않는다.

## 화면 시나리오

- **본문 파일에 `화면 시나리오:` 줄이 있으면 줄마다 그 시나리오를 head 에서 검증 스킬의 Drive 로 조작해 스크린샷을 그 이름으로 남기고 통과 조건으로 판정한다 — 꼬리에 `· BASE <판정>` 이 붙은 줄은 base worktree 에서도 같은 시나리오를 돌려(Launch 를 그 경로에서) 스크린샷 이름 앞에 `base-` 를 붙이고, 판정은 `screen-scenarios.md`「화면 시나리오 실행」 의 표다 — BASE 거짓·head 참만 통과이고, BASE 참(불성립)·BASE 못 돌림(미실행)은 NOTES 다. 꼬리가 없는 줄은 head 만 돌린다** — BASE 판정을 구현 세션의 본문 줄로 받으면 코드를 쓴 쪽의 판정이 push 근거가 된다(*"Only a verdict from an agent that did not write the code counts"*).
- **시나리오 줄을 다 돈 뒤에도 검증 스킬 「변경 검증」 절의 「입력 없음」 경로(1번 파일로 기능을 고른다)를 돈다 — 시나리오가 이미 조작한 진입 경로는 다시 돌지 않는다** — 시나리오는 화면 줄을 단 task 만 덮는다. 그 증거는 `스크린샷:` 칸에 싣는다.
