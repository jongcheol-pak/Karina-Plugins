# 화면 시나리오 실행 · 화면 확인 블록

> `report-format.md` 에서 떼어 낸 조건부 참조다 — plan 에 `**화면**` 줄이 있거나, 앱 조작으로 화면을 확인하거나, 사용자에게 스크린샷을 보이는 보고(화면 확인 블록)를 낼 때만 읽는다. 「화면 시나리오 실행」 은 루프 중 앱 조작 시점에도 읽힌다.

## 화면 시나리오 실행

**task 에 `**화면**` 줄(서식 `../../plan/references/plan-template.md`「작업 단계」)이 있으면 `AGENTS.md` 의 `Verify (앱 조작)` 줄이 가리키는 검증 스킬로 그 시나리오를 HEAD 에서 돌리고, 스크린샷을 그 스킬의 Evidence 위치에 줄에 적힌 이름으로 남겨 통과 조건으로 판정한다.** 순서는 그 스킬의 Launch → Doctor → Drive → Evidence → Cleanup 이고, 증거 기준은 `report-format.md`「사실 주장의 실측」 이다. 계획 시점에 정한 시나리오를 그대로 돌려야 실행 시점의 즉흥 설계가 판정을 대신하지 않는다.

- **task 루프의 화면 시나리오(회차 끝에 모아 도는 것 포함)는 메인 세션이 직접 돌리고 서브에이전트에 맡기지 않는다** — 맡기면 서브에이전트가 맥락을 다시 읽고 앱 기동·정리를 되풀이하는 동안 메인은 시한 없이 대기만 한다(2026-11-12 Karina 체인 plan 7 — 52분, 도구 호출 297회). 로컬 게이트의 `gate-verifier` 가 같은 시나리오를 다시 도는 것은 작성자와 다른 쪽의 독립 판정이라 이 규칙 밖이다(`local-gate.md`「본문 파일」).
- **검증 스킬을 Launch 하기 전마다 화면 가리기를 걷는다 — `../../SCREEN-COVER.md`「언제 끄고 켜는가」(보유자 `implement:<레포 루트>`). 다시 덮는 것은 task 마다가 아니라 회차 끝 「소요 기록」 과, 회차 중간에 멈추는 보고 직전이다** — 가리기가 켜진 모니터는 마우스 입력이 막혀 조작이 실패하고, task 사이에 덮으면 다음 task 의 조작이 다시 막힌다.
- **검증 스킬이 없으면(`Verify (앱 조작)` 줄이 없거나 「없음」) 화면 줄을 그대로 HUMAN-VERIFY 로 옮기고, 커밋 본문에 `화면: 미촬영(HUMAN-VERIFY) · 스크린샷 <이름> · 시나리오 <조작 순서> · 통과 조건 <조건>` 줄을 남긴다** — 시나리오·스크린샷 이름·통과 조건을 그대로 적어야 사용자가 같은 것을 돌린다. 커밋 줄이 없으면 체인 끝 게이트가 화면 task 를 찾지 못해 화면 게이트가 걸리지 않는다(`../../chain-plan/references/chain-end-push.md`「체인 끝 게이트」).
- **`(BASE 대조)` 가 붙은 줄은 BASE 에서도 같은 시나리오를 돌린다** — `git worktree add --detach <스크래치>/base-<sha7> <plan.md 의 > BASE:>` 로 BASE 를 받고, 검증 스킬의 Launch 를 그 worktree 경로에서 돌린 뒤 같은 Drive·Evidence(스크린샷 이름 앞에 `base-`)·Cleanup 을 거쳐 `git worktree remove <경로>` 로 지운다. 사용자의 체크아웃은 건드리지 않는다(선례 `local-gate.md`「worktree 와 빌드 캐시」). **같은 경로가 이미 등록돼 있으면(지난 실행이 중간에 끊긴 것) 만들기 전에, 삭제가 거부되면 그 자리에서 로컬 게이트와 같은 기준으로 지운다 — `detached` 이고 HEAD 가 `<plan.md 의 > BASE:>` 와 같을 때만 `--force`, 그 밖이거나 실패하면 「worktree 미삭제 — <경로> · <오류 줄>」 을 최종 보고에 싣고 계속한다** — 남은 worktree 가 있으면 `git worktree add` 가 같은 경로에서 실패하고, 판정은 이미 끝나 정리 실패가 결과를 바꾸지 않는다.
- **참/거짓을 적기 전에 남긴 스크린샷(`base-` 짝 포함)을 Read 로 열어 통과 조건과 대조한다 — 검증 스킬 출력·로그 문구만으로 판정하지 않는다** — 스킬이 「성공」 을 내도 화면이 통과 조건과 다를 수 있고, 이미지를 직접 보는 것만 그 차이를 잡는다(pstack guide 06 *"Ask for the proof as an artifact you can inspect yourself"* — `https://github.com/cursor/plugins/blob/ae5650febf4320793844c12c4adaa937f417f8da/pstack/docs/guide/06-verify-and-ship.md`).
- **판정은 넷으로 갈린다 — 「BASE 에서 거짓·HEAD 에서 참」 만 통과다** — 변경 전에도 참인 시나리오는 이 변경을 재지 않는다.

  | HEAD | BASE | 판정 | 처리 |
  |---|---|---|---|
  | 거짓 | — | 실패 | 그 task 의 검증 실패다 — `loop-exceptions.md`「실패 처리」 |
  | 참 | 거짓 | 통과 | `[x]` |
  | 참 | 참 | BASE 대조 불성립 | 시나리오가 계획을 잘못 옮긴 것이면 1회만 고쳐 두 쪽을 다시 돌린다(원래 문면과 사유를 그 task 에 남긴다). 그래도 참이면 다른 검증이 통과한 task 를 `[x]` 로 닫고 Progress Log 에 `판정:` 줄을 남긴다 |
  | 참 | 못 돌림 | BASE 미실행 | worktree·Launch 실패 사유를 적고, 다른 검증이 통과한 task 를 `[x]` 로 닫는다 |

- **위 표의 뒤 두 판정은 통과로 적지 않고 재시도 루프도 돌리지 않는다 — 커밋 본문과 최종 보고 「기계로 확인 못 한 항목」 에 `화면 — BASE 대조 불성립(미검증)` 또는 `화면 — BASE 미실행(미검증)` 으로 싣는다** — 통과로 적으면 BASE 를 재지 않은 채 게이트가 열리고, 코드로 풀 수 없는 실패를 실패 카운터에 태우면 「동일 원인 3회」로 루프가 선다.
- **커밋 본문에 판정 한 줄을 남긴다 — `화면: HEAD <참|거짓> · 스크린샷 <이름> · 시나리오 <조작 순서> · 통과 조건 <조건> [· BASE <거짓|참|미실행>]`** — 완료 리뷰가 이 줄로 시나리오를 돌렸는지 대조하고, 체인 끝·디버깅 게이트는 `plan.md` 대신 이 줄에서 다시 돌 시나리오를 얻는다(`local-gate.md`「디버깅 단독」·`../../chain-plan/references/chain-end-push.md`「체인 끝 게이트」).
- **시나리오·통과 조건 칸에는 ` · ` 를 쓰지 않는다 — 단계는 `→` 로 잇는다** — 칸 구분자가 ` · ` 라, 칸 안에 쓰면 칸이 어디서 끝나는지 가를 근거가 칸 이름뿐이다.
- **남긴 스크린샷마다 `## Progress Log` 에 `화면 경로: <이름> — <경로>` 한 줄을 남긴다 — 경로의 사용자 홈·임시 폴더 앞부분은 `%TEMP%\…`·`~/…` 로 바꾸고, `base-` 짝도 적는다** — 최종 보고 「화면 확인」 블록이 이 줄에서 경로를 옮긴다. 커밋 본문에는 이름만 둔다. 절대경로에는 사용자 이름이 들고, `plan.md` 를 추적하는 레포는 Progress Log 도 커밋·push 된다(`report-format.md`「plan 파일 커밋」).

### 완료 리뷰 대조

> `completion-reviewer` 가 `**화면**` 줄이 있는 task 를 볼 때 읽는다. 그 줄이 있는 task 에서만 쓰이는 대조라 리뷰어 정의가 아니라 화면 판정 줄 서식의 정본 곁에 둔다.

- **`**화면**` 줄이 있는 task 는 커밋 본문에 `화면:` 판정 줄(HEAD 판정·스크린샷 이름·시나리오·통과 조건, `(BASE 대조)` 면 BASE 판정)이 있는지 보고, 없거나 시나리오·통과 조건 칸이 비면 지적한다. 판정 없이 확인함으로 적혔으면 BLOCKER 다 — `BASE 대조 불성립(미검증)`·`BASE 미실행(미검증)` 표기가 있는 `[x]` 와, 검증 스킬이 없을 때의 `화면: 미촬영(HUMAN-VERIFY)` 줄은 정상이다. 미촬영이 아닌데 그 스크린샷의 Progress Log `화면 경로:` 줄이 없어도 지적한다** — 돌리지 않은 시나리오가 통과로 남고, 보고 「화면 확인」 블록에 경로가 빈다.

## 화면 확인 블록

**사용자에게 스크린샷을 보이는 모든 보고 — push 전 화면 확인 요청(로컬 게이트 · 체인 보고)과 이 스킬·디버깅의 최종 보고 — 는 이 서식 하나로 싣는다.** 자리마다 서식이 다르면 어떤 자리는 이름만, 어떤 자리는 「확인하라」 만 남는다.

```
화면 확인 대기 — 아래 스크린샷을 열어 본 뒤 답한다

<로컬 게이트 — HEAD <sha7> | push 대기 없음 — <사유>>
  - <이름> — <절대경로>
  - base-<이름> — <절대경로>
  - <이름> — 없음 — <사유>
  - 기각 변형 <이름> — <절대경로>
  코디네이터 판정: <`## 화면` 의 그 줄 원문 — 있을 때만>

push 대기 없음 — 시나리오 밖 조작
  - 변경 검증 <기능> · <진입 경로> — <절대경로>

확인했으면 「화면 확인함」 으로 답하거나 다시 요청
```

- **push 를 기다리지 않는 블록(머리가 모두 `push 대기 없음 — …`)은 첫 줄을 「화면 증거 — 열어 보는 것은 선택이다」 로 바꾸고 「화면 확인함」 끝 줄을 뺀다** — 답할 것이 없는데 답을 요구하면 사용자는 기다리는 push 가 있다고 읽는다. 대기 머리가 하나라도 있으면 틀은 그대로이고 기다리지 않는 머리는 그 안에 둘째로 둔다.
- **「변경 검증」 줄은 `gate-verifier` `스크린샷:` 칸의 그 줄을 그대로 옮긴다 — 머리는 `push 대기 없음 — 시나리오 밖 조작` 이고 화면 게이트를 열지 않는다(`local-gate.md`「화면 게이트」)** — 시나리오 밖에서 조작한 화면은 검증자가 판정했고, 사용자에게는 보이기만 한다(사용자 답 「보이기만」).

- **목록은 이름에서 출발한다 — 게이트 본문 파일 `## 화면` 줄(이 스킬은 plan `**화면**` 줄, plan 없는 디버깅은 `../../karina-systematic-debugging/references/investigation-log.md`「화면 증거 (UI 재현)」 의 짝)의 이름마다 한 줄이고, `(BASE 대조)`·`base-` 짝과 기각 변형도 한 줄씩이다** — 경로 칸에서 출발하면 찍히지 않은 스크린샷이 줄째 빠져 「확인하라」 만 남는다.
- **경로는 그 자리가 받은 출처에서만 온다 — `gate-verifier` `스크린샷:` 칸(재사용이면 판정 기록) · Progress Log `화면 경로:` 줄 · 체인 워커 `--body` 의 `화면 확인:` 칸. `%TEMP%\…`·`~/…` 표기는 절대경로로 펼치고, 싣기 전에 모든 경로의 실재를 한 번의 셸 호출(`ls -d <경로…>` · `Test-Path`)로 잰다** — 증거 폴더를 뒤져 짐작한 경로는 다른 실행의 스크린샷일 수 있고, 증거는 기한이 지나면 지워진다(`../../TEMP-FILES.md`).
- **경로가 없는 이름은 줄을 지우지 않고 `없음 — <사유>` 로 적는다 — 미촬영이면 `미촬영(HUMAN-VERIFY): 시나리오 <…> · 통과 조건 <…>`(`화면 시나리오:` 줄·`**화면**` 줄에서), 파일이 사라졌으면 `파일 없음(<경로>) — 증거 기한 정리일 수 있다 · 게이트를 다시 돌리면 다시 찍는다(판정 재사용이면 같은 경로를 다시 읽는다)`, 출처에 칸이 없으면 `경로 미수신 — <어느 출처에 없었나>`** — 사용자가 무엇을 볼 수 없는지와 대신 무엇을 하면 되는지가 그 줄에 있어야 한다.
- **블록은 로컬 보고에만 싣는다 — 커밋 메시지에는 싣지 않는다** — 절대경로에 사용자 이름이 든다.
