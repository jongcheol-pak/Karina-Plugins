# 재사용 범위 판정 — 두 커밋 사이 변경이 검증을 다시 돌 필요가 있는가

> 앞서 검증한 커밋에서 HEAD 가 움직였을 때 그 검증을 재사용할 수 있는지 가르는 정본이다. 가리키는 자리 — `local-gate.md`「판정 재사용」 ⓐ·「중간 단계」·「디버깅 단독」 · `gate-verifier-conditional.md`「직전 판정 재사용」·「중간 단계」 · `../../chain-plan/references/continuation.md`「코디네이터 검증」(`run-verify.py` 의 `--reuse-docs`·`--reuse-glob`). 결과는 「문서뿐」 · 「선언 경로 포함」 · 거짓 셋이고, 「선언 경로 포함」 에서 무엇을 다시 도는지는 이 절 끝 불릿이 정한다.

## 재사용 범위 판정

- **`<A>..<B>` 의 바뀐 파일(`git diff --name-only --no-renames <A>..<B>`)이 전부 문서(`.md`·`.txt`)이고 그중에 `AGENTS.md`·검증 매핑 문서가 없고 그 레포 검증 매핑(`AGENTS.md` 또는 그것이 지목한 문서)이 그 경로에 명령을 걸지 않고, 바뀐 각 파일의 이름이 `.md`·`.txt` 밖 추적 파일에 따옴표 바로 앞 문자열로 나오지 않으면(`git grep -l -F -e '<이름>"' -e "<이름>'" -- . ':!*.md' ':!*.txt'` 이 비었다 — 레포 최상위에서) 판정은 「문서뿐」 이다** — 문구만 바뀐 변경을 다시 검증하면 같은 판정을 두 번 산다(*"a wording-only change gets none"*). 매핑 문서를 고친 변경은 문구가 아니라 어느 검사가 도는지를 바꿔 재사용하지 않는다(원문 autopilot-full *"a change to which checks run"* — `https://github.com/cursor/plugins/blob/ae5650febf4320793844c12c4adaa937f417f8da/pstack/skills/poteto-mode/playbooks/autopilot-full.md`). 검증 매핑이 `*.md` 에 명령을 거는 레포(이 하니스)는 늘 거짓이다. 이름 대조는 빌드가 읽는 문서를 거른다 — Karina 는 `include_str!` 로 `SKILL.md`·`fixtures/*.txt` 를 빌드에 넣어(2026-11-11 실측), 확장자만 보면 그 파일만 고친 수정 커밋이 재검증 없이 push 된다.
- **그 레포 `AGENTS.md` 에 `Gate 재사용 경로` 줄이 있으면, 문서 조건을 채우지 않는 파일이라도 그 glob 에 걸리면 선언 경로 파일로 친다 — 판정은 `AGENTS.md` 폴더에서 `git diff --name-only --no-renames <A>..<B> -- ':(top)' ':(exclude,glob)<g1>' ':(exclude,glob)<g2>' …` 의 남은 줄이 위 문서 조건을 모두 채우는가다. 단 선언 glob 에 걸려도 검증 매핑이 명령을 거는 파일과 `Gate 필수 경로` glob 에 걸리는 파일은 선언 경로로 치지 않는다(남은 줄에 그대로 둔다). 선언 경로 파일이 하나라도 있고 나머지가 문서 조건을 채우면 판정은 「선언 경로 포함」 이다. 둘 다 아니면 거짓이다. 선언 경로 파일에는 따옴표 앞 이름 대조를 걸지 않는다** — 어느 코드가 테스트를 다시 돌 필요가 없는지는 하니스가 경로로 추측하면 틀린다(2026-11-14 기각 — Rust 테스트가 소스 파일 안 `#[cfg(test)]` 라 경로로 가를 수 없다). 레포가 선언하면 그 책임이 레포에 있다(사용자 답 「레포 선언 경로」). glob 은 `Gate 필수 경로` 와 같은 git `:(glob)` 의미(`**` 하위 전체 · `*` 한 단계)이고, exclude 는 cwd(`AGENTS.md` 폴더) 기준으로 풀리며 `':(top)'` 이 레포 전체를 잰다 — `.` 만 쓰면 하위 폴더 세션에서 그 밖 변경이 빠져 거짓 「문서뿐」 이 난다. 이름 대조를 걸지 않는 것은 레포가 재검증 불필요를 명시한 경로라서다 — 걸면 코드가 이름으로 부르는 파일(`style.css` 등)은 늘 걸린다(사용자 답 「적용 안 함」).
- **「선언 경로 포함」 은 테스트 명령만 재사용한다 — 검증을 통째로 건너뛰는 자리(`local-gate.md`「판정 재사용」 ⓐ)는 「문서뿐」 만 받고, 「선언 경로 포함」 이면 직전 판정을 넘겨 검증자를 부른다. 검증자는 직전에 exit 0 이던 테스트 명령만 재사용하고 head 빌드(base 빌드는 하지 않는다)·`늘지 않`·`--since <` 감사(base 쪽은 빌드 없이)·4번 형식 검사·7번 게이트 완화 검사·3번 조작·화면 시나리오(head)는 돈다. 화면 시나리오 줄의 `· BASE` 꼬리는 `gate-verifier-conditional.md`「화면 시나리오」 의 작성자 `base-` 스크린샷 대조가 되면 그것으로 하고, 아니면 돌지 않고 NOTES 에 `BASE 대조 생략(재사용)` 을 적는다** — 코드는 화면과 빌드 산출물을 바꿀 수 있고, 새로 만든 head worktree 에는 산출물이 없어 빌드 없이는 조작할 앱이 없다. 감사·형식 검사·게이트 완화 검사는 테스트가 아니라 CI 체크 끄기 같은 변경을 잡는 자리다(사용자 답 「테스트·빌드만 면제」 를 승인 때 테스트만으로 좁혔다). 「중간 단계」 와 같은 형태다.
