# 최종 리뷰

> `karina:implement`가 **검증 4번을 통과한 뒤 1회** 읽는다. 회차 끝에만 쓰이는 절차라 `SKILL.md` 본문에 두지 않는다 — `report-format.md`와 같은 이유이고, 그 둘은 같은 지점에서 연달아 읽힌다.

## 완료 순서

- **완료 순서는 「4번 검증 → Deferred 판정·대장 이관(아래 「Deferred 판정」) → 함정 기록(아래 「함정 기록·결정 큐잉」) → 리뷰 → 필터 패스 등재분 대장 이관 → 완료 시각 기록(`report-format.md`「소요 기록」) → 추적 레포면 plan 파일 커밋(`report-format.md`「plan 파일 커밋」) → PR 열기(`pr-flow.md`「PR 열기」 — main 직행이면 같은 파일 「main 직행」 의 push) → 최종 보고」다** — 리뷰어가 대장 판정 결과와 함정 기록을 검사하므로 그 둘이 리뷰보다 먼저다. 필터 패스(아래 「필터 패스」)가 리뷰 뒤에 `[등재]` 로 남긴 항목은 앞의 대장 이관이 이미 지나간 뒤에 생기므로 그 자리에서 한 번 더 옮긴다 — 안 옮기면 `plan.md` 와 함께 다음 회차에 덮어써진다.

## Deferred 판정

- **`## Deferred / Follow-up`의 항목을 전부 판정한다 — 등재 전에 「지금 고칠 것인가」를 먼저 가른다** — 등재분은 그 레포의 **Deferred 대장**(위치는 그 레포 `AGENTS.md` 의 `## Plan Location`)으로 옮기고, **대장이 없는 레포면 등재가 아니라 `[미등재:대장 없음]`으로 닫는다**(판정 3조건과 하한선은 `../../plan/references/deferred-rules.md`).

## 함정 기록·결정 큐잉

이번 회차에 **① 같은 원인으로 2회 이상 막힌 것**이나 **② 다음 작업자가 모르면 다시 걸릴 함정**이 있었는지 판정하고, 있으면 레포 `docs/conventions.md` 에 기록한다 — 판정·형식·위치는 `../../REPO-CONVENTIONS.md` 「쓰기」 가 정본이고 완료 때 그 절만 Read 한다.

- **이 회차의 보류·기각 `[DECISION]` 을 여기서 1회 일괄 큐잉한다 — 대상은 plan 의 `## Out of Scope` 기각 · 완료 시점에 남은 `## Deferred / Follow-up` 보류 · 구현 중 새로 생긴 것과 기록된 보류·기각의 번복이고, 형식·입도·하네스 레포 예외는 `../../llm-wiki/references/queue-rules.md`의 K 5-2가 정본이다** — 그 규약의 배치 시점은 여기 하나다(채택은 코드·커밋이 담아 큐잉하지 않는다). vault 판정은 `../../WIKI.md` §0 이다. **`queue-rules.md` 는 파일째 읽지 않는다 — K 5~K 5-2 와 K 6 절만 `grep -n '^### K' <queue-rules.md 경로>` 경계로 Read 한다**(K 5-2 가 K 5 의 게이트·폴백과 K 6 커밋에 기댄다).

## 절차

- **리뷰어를 부르기 전에 증거 대조를 1회 돌린다 — `"<skill>/../plan/scripts/check-plan.ps1" "<plan.md>" -Base <BASE>` 를 work-clock 과 같은 호출형(`report-format.md`「소요 기록」)으로 부르고, `<BASE>` 는 아래 BASE SHA 와 같은 값이다** — `[x]` 는 완료 커밋보다 먼저 바뀌어(`../SKILL.md`「자율 루프」 4번) 커밋도 검증 기록도 없이 닫힌 task 가 리뷰까지 기계 검사 없이 온다. 커밋 본문을 증거 자리로 정한 것은 pstack multi-phase-plan 의 *"Check a box only when its evidence exists"* 를 들인 것이다(`https://github.com/cursor/plugins/blob/f713f14203cd6420cec13cd7c55c32d598dbab68/pstack/skills/poteto-mode/playbooks/multi-phase-plan.md`).
  - **exit 1 이면 걸린 task 마다 그 task 의 검증 명령을 다시 돌려 `git commit --allow-empty` 로 보충 커밋(제목 `{유형}: T<N> — 검증 기록 보충` · 본문에 검증 결과)을 남기고 다시 돌린다** — 이력을 고치는(rebase·amend) 대신 증거를 더한다. 체크박스는 이미 `[x]` 라 보충 커밋은 체크박스 갱신과 따로 부른다.
  - **exit 2 나 출력이 없으면 `증거 대조 미실행 — <사유>` 줄을 만든다.** 대조 출력이나 그 줄을 리뷰어 전달물에 싣는다 — 미실행이면 리뷰어가 커밋 본문을 직접 대조한다.
- **리뷰어를 부를 때마다(재호출 포함) 그 직전에 이 세션 전사 요약을 만든다 — `python "<skill>/../reflect/scripts/digest_transcript.py" --audit --out <스크래치 경로>/completion-digest.txt`(`<skill>` 은 `../SKILL.md` 의 폴더). exit 2·3 이면 `전사 요약 미실행 — <출력 원문 요지>` 줄을 만들고 리뷰는 그대로 부른다. 아래 경량 plan 으로 리뷰어를 부르지 않으면 만들지 않는다** — 판정 줄 없이 고른 갈림길은 git·plan 어디에도 흔적이 없어 전사가 유일한 재료이고, 재호출 전 수정 구간은 옛 요약에 없다. 요약 실패로 리뷰를 막으면 나머지 검사 항목까지 잃는다.
- **`completion-reviewer` 서브에이전트를 호출한다 — 호출 전후 작업 트리 확인은 `../../READONLY-SUBAGENTS.md`「호출 전후 확인」 대로다** — 회차 전체를 계획과 대조하는 것은 각 task를 지나온 쪽이 보기 어려운 각도다. 전달: `plan.md` 경로 · BASE SHA(`plan.md` `## Goal` 아래 `> BASE:` 줄의 값 — 커밋 제목으로 짐작하면 사이에 낀 커밋이 diff 범위를 틀어 놓는다) · HEAD SHA · `AGENTS.md` 경로 · 위 증거 대조 출력(또는 미실행 줄) · 전사 요약 경로(또는 미실행 줄).
  - **경량 plan(`## Goal` 에 `> 경량:` 줄 — 서식 `../../plan/references/plan-template.md`「경량 plan」)이고 `git diff --name-only <BASE>..HEAD` 에서 경로가 전부 문서·이미지인 `[면제 ①]` Files 줄의 경로를 뺀 수(셈법은 `../../plan/references/interview.md`「경량 계획」 의 「파일 2개 이하」)가 3파일 미만이면 부르지 않는다 — 대신 이 세션이 `../../../agents/completion-reviewer.md`「검사 항목」 다섯(요구 ↔ 산출물 · task 완료 상태의 진실성 · Goal 성공 기준 · Deferred 처리 · 함정 기록)을 체크리스트로 재고, 항목마다 `<항목> — <참|거짓> — <근거 명령·출력>` 줄을 최종 보고에 싣는다** — 1~2파일 회차(같은 셈법)에 리뷰어 한 번(수 M 토큰)을 줄이되, 한 항목이라도 빠지면 그 항목을 아무도 재지 않는다. 위 증거 대조는 그대로 돌고, 거짓이 남으면 고친 뒤 다시 잰다. 같은 셈법으로 3파일 이상이면 계획 시점 실측이 틀린 것이라 부른다.
- **리뷰어는 백그라운드로 띄우고, 완료 통지를 기다리는 동안 레포 파일을 고치지 않는 일(`report-format.md` Read · 최종 보고·PR 본문 초안)만 한다** — 리뷰 대기 중 다른 파일을 만지면 다음 커밋이 그것을 함께 담아 커밋 단위가 엉킨다(하니스 레포 관측 2026-09-02 — 한 회차에 3회).
- **결과를 받아 판정한 뒤에 완료 선언으로 간다** — 호출만 하고 다음으로 넘어가면 리뷰가 없는 것과 같다.
- **BLOCKER·MAJOR는 고치고 다시 호출한다** — 지적이 남은 산출물을 통과시키면 그 결함이 다음 회차로 간다. MINOR 는 아래 「필터 패스」가 가른다. (중계 모드 예외는 `../../plan/references/relay-mode.md`「중계 모드」)
  - **완료 리뷰 지적은 고치기 전에 지적의 명령을 다시 돌린다 — 같은 실패가 나오면 고치고, 나오지 않으면 재실행 출력으로 기각한다(`기각 — <요지> — <재실행 명령·출력 요지>`)** — 리뷰어는 diff 와 문서만 보고 호출 사슬 전체를 보지 못해, 「여기 X 가 올 수 있다」 같은 가정 경로를 그대로 고치면 증거 없는 가드가 늘고 범위가 번진다. 증명 책임을 지적한 쪽에 두는 것은 pstack interrogate 의 *"A finding survives only when a run proves it."* · *"Keep a finding when the output shows the failure and the failure breaks the intent. Drop the rest."* 를 들인 것이다(`https://github.com/cursor/plugins/blob/ab1f702ce8e8b6557edb56b09f52cde8bfb83f17/pstack/skills/interrogate/SKILL.md`).
  - **근거에 실패를 보이는 출력이 없는 완료 리뷰 BLOCKER·MAJOR(줄이 있다는 출력·파일:라인 인용뿐인 것)는 MINOR 로 내려 아래 「필터 패스」로 보낸다 — 보안 지적만 예외로 등급을 유지한다** — 전달한 검증 출력·커밋 본문의 실패 출력 인용은 실패를 보이는 출력이다. 이 둘(재실행·강등)은 완료 리뷰에만 걸린다 — `plan-reviewer` 는 명령을 돌리지 못해 아래 기준 넷만 쓴다.
  - **계획 리뷰 지적과 재현된 완료 리뷰 지적은 반증 출력이 있는 오탐만 기각한다.** 기준은 넷이다(pstack interrogate 의 lead-judgment 를 들인 것 — `https://github.com/cursor/plugins/blob/8b3326d99fd4b993cb33a24dad8af03175c642c5/pstack/skills/interrogate/references/lead-judgment.md` · upstream 은 `ab1f702c` 에서 이 파일을 지웠다).
    - ⓐ 「X 가 올 수 있다」 류는 호출부를 추적해 상위에서 이미 막혀 있음을 보이는 명령 출력(반증 출력)이 있으면 기각한다.
    - ⓑ 「나라면 다르게 했다」·조기 추상화 권유처럼 현재 방식의 구체적 문제를 보이지 않는 지적은 출력 없이 기각한다.
    - ⓒ 이번 회차가 쓰지 않은 코드를 겨누거나 레포 전체 관례와 같은 패턴을 지적하는 것(맥락 부족)은 그 관례를 보이는 출력으로 기각한다.
    - ⓓ 보안·정확성 지적은 반증 출력 없이는 기각하지 않는다 — 완료 리뷰의 정확성 지적은 재현된 것에만 걸린다.
  - **기각마다 `기각 — <지적 요지> — <반증 명령·출력 요지>` 줄을 최종 보고에 싣고, 재호출 때 그 줄들을 전달물에 더한다** — 리뷰어가 반증을 다시 대조할 수 있어야 같은 지적이 되풀이되지 않는다.
  - **같은 지적을 두 번째로 기각하게 되면 기각하지 않고 최종 보고 「남은 이슈」 에 원래 등급으로 올리고, 그 지적으로는 다시 부르지 않는다** — 기각과 재지적이 오가는 것을 멈추는 상한이다.

## 전사 대조

`completion-reviewer` 가 전사 요약 경로를 받았을 때 이 절대로 본다. 출처는 pstack show-me-your-work 「Audit the log against the transcript」 다 — 고정 위치 `https://github.com/cursor/plugins/blob/ce649c03ac3b75b6ae80cbd15b7e2c536caedb5a/pstack/skills/show-me-your-work/SKILL.md` · *"A fork, pivot, or abandoned approach that shaped the work but isn't logged is a gap. Add it."*

- **대조 범위는 요약의 마지막 plan 진입 표지 뒤에 오는 첫 implement 진입 표지 뒤다 — plan 표지가 없으면 첫 implement 표지 뒤, 둘 다 없으면 전체** — 표지는 `T: Skill karina:<이름>` 줄과 `<command-name>/karina:<이름>` 이 든 `U:` 줄이다. 그 앞의 인터뷰 결정은 plan Decisions·인터뷰 줄이 담고, 마지막 implement 표지에서 자르면 정지 뒤 재발동한 회차의 앞 구간이 빠진다.
- **지적 대상은 `A:` 줄의 갈림길 선택·방향 전환·버린 접근과 `T: Bash` 의 되돌림 명령(`git restore`·`git checkout --`·`git revert`·`git reset`) 가운데 Progress Log `판정:`·`판정(정정):` 줄이나 plan Decisions 에 짝이 없는 것이다** — plan task 를 그대로 수행한 단계·기계적 재시도·이미 판정 줄이 있는 것은 대상이 아니다. 판정 줄은 실행 세션만 쓰고 최종 보고가 그 줄을 옮겨 실으므로, 짝이 없는 결정은 리뷰도 보고도 지나지 않고 사라진다.
- **등급은 MINOR 이고, 근거 칸에 요약 줄 원문을 인용한다** — 산출물이 아니라 기록이 빠진 것이라 완료를 막지 않는다. 인용이 없으면 호출자가 그 갈림길을 찾지 못한다.
- **호출자는 아래 필터 패스 ⓐ 로 빠진 판정 줄을 Progress Log 끝에 덧붙이고 줄 끝에 `(완료 리뷰 전사 대조)` 를 단다 — 앞 줄을 고쳐 쓰지 않는다** — *"Correct the log, not the story."* 사후에 붙였다는 표지가 있어야 그 자리에서 쓴 판정과 갈린다.

## 필터 패스

**리뷰어는 전부 보고하고, 거르는 것은 호출자인 이 세션이다**(`../../DESIGN.md` §3-2 — 가이드가 심각도 억제 문구를 금지하는 대신 요구하는 절차가 이것이다). **거르는 절차가 없으면 리뷰어의 보고가 그대로 대장이 된다**(실측 2026-09-10 — 대장 순증 전량이 「리뷰 반영」 커밋에서 나왔다).

**종결로는 둘뿐이다.**

| # | 종결로 | 언제 |
|---|---|---|
| ⓐ | **고친다** | 처방이 이미 정해져 있다 — 무엇을 할지 정하는 데 사용자·계획이 필요 없다 |
| ⓑ | **버린다** | 실해가 관측되지 않았거나, 지시하는 액션이 파일 수정이 아니다(교훈·작성법·미착수 제안) |

- **대장 등재는 종결로가 아니다.** 예외는 하나 — **처방을 고르는 데 사용자 결정이나 별도 계획이 필요한 것**이며, 그때만 `## Deferred / Follow-up` 에 `[등재]` 로 적고 하한선 두 축을 함께 만족시킨다(`../../plan/references/deferred-rules.md`). **그 등재분은 위 「완료 순서」대로 리뷰가 끝난 뒤 대장으로 옮긴다** — 회차의 대장 이관은 리뷰 전에 이미 지나갔다. **그 판단이 서지 않으면 ⓑ다** — 애매한 것을 올려 두는 것이 대장을 늘렸다.
- **ⓑ로 닫은 것도 `[미등재:<사유>]` 로 남긴다** — 흔적 없이 지우면 다음 회차가 같은 것을 또 발견한다. 화면에는 내지 않는다(`report-format.md`「남은 이슈」).
- **필터 패스가 등재 문턱보다 먼저다** — 리뷰 소스의 지적은 여기서 먼저 갈리고, **걸러지지 않은 것만** `deferred-rules.md` 의 하한선을 통과한다. 순서가 반대면 리뷰가 대장의 최대 유입원이 된다.
- **이번 회차가 낸 흠을 다음 회차에 넘기는 것은 처리가 아니라 전가다** — ⓐ의 문턱을 낮게 잡는다.
- **같은 지적이 3회 연속이거나, 고칠 때마다 새 MINOR가 나서 라운드가 늘면 멈춘다** — 이것은 `../SKILL.md`「멈추는 넷 — 그리고 목록 밖의 넷」의 목록 밖 정지이고, 라운드는 「동일 원인 3회 실패」·「같은 수단을 3회 반복」처럼 3에서 센다.
  - **멈추기 전에 이 회차가 걷은 화면 가리기를 다시 덮는다 — `../../SCREEN-COVER.md`「언제 끄고 켜는가」**
- **리뷰어가 호출되지 않는 환경이면 그 사실을 최종 보고에 적고 진행한다** — 리뷰 부재를 통과로 적지 않는다.
- **plan 승인이 이 호출의 승인이다** — 리뷰 지점에서 사용자에게 묻지 않는다.
