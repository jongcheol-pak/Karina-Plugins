## 절차

- **리뷰어를 부르기 전에 증거 대조를 1회 돌린다 — `"<skill>/../plan/scripts/check-plan.ps1" "<plan.md>" -Base <BASE>` 를 work-clock 과 같은 호출형(`report-format.md`「소요 기록」)으로 부르고, `<BASE>` 는 아래 BASE SHA 와 같은 값이다** — `[x]` 는 완료 커밋보다 먼저 바뀌어(`../SKILL.md`「자율 루프」 4번) 커밋도 검증 기록도 없이 닫힌 task 가 리뷰까지 기계 검사 없이 온다. 커밋 본문을 증거 자리로 정한 것은 pstack multi-phase-plan 의 *"Check a box only when its evidence exists"* 를 들인 것이다(`https://github.com/cursor/plugins/blob/ae5650febf4320793844c12c4adaa937f417f8da/pstack/skills/poteto-mode/playbooks/multi-phase-plan.md`).
  - **exit 1 이면 걸린 task 마다 아래 위반 코드대로 증거를 얻어 `git commit --allow-empty` 로 보충 커밋(제목 `{유형}: T<N> — 검증 기록 보충` · 본문에 얻은 줄)을 남기고 1번만 다시 돌린다** — 이력을 고치는(rebase·amend) 대신 증거를 더한다. 걸린 task 의 체크박스는 이미 `[x]` 라 hook 이 보충 커밋을 막지 않는다 — `[x]` 를 이제 고쳐야 하면 Edit 와 커밋을 별도 호출로 한다(`loop-exceptions.md`「실패 처리」). 코드 뜻의 정본은 `check-plan.ps1` 머리 주석이다.
    - `no-task-commit`·`no-commit-evidence` — 그 task 의 검증 명령을 다시 돌려 `검증 결과:` 를 남긴다. 4번이 같은 HEAD 에서 그 명령을 이미 돌렸으면 다시 돌리지 않고 4번 출력의 그 명령 줄을 옮긴다.
    - `acceptance-evidence` — 그 task 의 `**Acceptance**` 항목마다 판정 명령을 HEAD 에서 다시 돌려 `Acceptance: <항목 요지> — 참` 줄을 항목 수만큼 남긴다(사람 눈이 필요한 항목은 `— HUMAN-VERIFY — <사유>`). 거짓이 나오면 줄을 남기지 않고 그 task 의 검증 실패로 고친다 — 재지 않은 Acceptance 로 닫힌 `[x]` 는 검증 전 `[x]` 와 같다.
    - `no-red-evidence` — 그 task 의 구현 파일을 task 직전 커밋 판으로 임시 복원해 케이스 RED 를 보고 되돌린 뒤 `RED(사후 — <sha7>^ 구현 복원):` 를 남긴다. 뒤 task 가 그 파일을 바꿨거나 복원 판으로 빌드되지 않으면 복원하지 않고 `RED: 미확인 — <사유>` 를 남긴다 — 뒤 변경까지 되돌리면 RED 가 무엇 때문인지 갈리지 않는다.
    - `no-screen-verdict`·`screen-false`·`screen-unshot` — 그 화면 시나리오를 HEAD 에서 돌려 판정 줄을 남기고, 거짓이면 그 task 의 검증 실패로 고친다. 검증 스킬로 끝내 못 돌렸으면 미촬영 줄에 `· 사유 <…> · 시도 <…>` 칸을 단다(`screen-unshot-attempt` 도 같다). **보충 커밋은 걸린 task 마다 하나다 — 판정은 그 task 의 `T<N>` 커밋 본문에서만 받고 다른 커밋의 지목 줄 `화면: T<N> …` 은 받지 않는다**(`screen-scenarios.md`「화면 시나리오 실행」) — 화면 판정을 task 단위로 바꾼 뒤(v3.48.0) 회차 끝에 화면 보충이 여럿 걸리는 것은 task 루프에서 판정을 건너뛴 것이라, 묶어 한 커밋으로 덮지 않는다.
    - **note(`red-unverified`·`screen-unshot-reason`)는 위반이 아니다 — 최종 보고 「HUMAN-VERIFY」 에 `T<N> <RED 미확인 | 화면 미촬영> — <사유>` 로 하나씩 싣는다.**
    - `remaining-issue` — 보충 커밋으로 닫지 않는다. 그 Deferred 항목을 고쳐 지우거나, 넘김 사유(`../../plan/references/deferred-rules.md`)가 실제로 있을 때만 그 사유를 항목에 적고 다시 돈다.
    - **다시 돌린 뒤에도 남은 task 증거 위반은 리뷰어 전달물에 싣고 완료 보고가 아니라 멈춤 보고로 낸다(위반 출력 원문 · `../SKILL.md`「멈추는 넷 — 그리고 목록 밖의 넷」 2번)** — 얻지 못한 증거는 남은 이슈가 아니라 미완료이고, 수단이 없는 증거는 위 note 가 HUMAN-VERIFY 로 받는다.
  - **exit 0·1 이 아니면(exit 2 · pwsh 부재·기동 실패 포함) 또는 출력이 없으면 `증거 대조 미실행 — <사유>` 줄을 만든다.** 대조 출력이나 그 줄을 리뷰어 전달물에 싣는다 — 미실행이면 리뷰어가 커밋 본문을 직접 대조한다.
- **리뷰어를 부를 때마다(재호출 포함) 그 직전에 이 세션 전사 요약을 만든다 — `python "<skill>/../reflect/scripts/digest_transcript.py" --audit --out <스크래치 경로>/completion-digest.txt`(`<skill>` 은 `../SKILL.md` 의 폴더 · `<스크래치 경로>` 는 `../../TEMP-FILES.md` 의 `scratch\`). exit 0 이 아니면(명령 없음 포함) `전사 요약 미실행 — <출력 원문 요지>` 줄을 만들고 리뷰는 그대로 부른다. 아래 경량 plan 으로 리뷰어를 부르지 않으면 만들지 않는다** — 판정 줄 없이 고른 갈림길은 git·plan 어디에도 흔적이 없어 전사가 유일한 재료이고, 재호출 전 수정 구간은 옛 요약에 없다. 요약 실패로 리뷰를 막으면 나머지 검사 항목까지 잃는다.
- **`completion-reviewer` 서브에이전트를 호출한다 — 호출 전후 작업 트리 확인은 `../../READONLY-SUBAGENTS.md`「호출 전후 확인」 대로다** — 회차 전체를 계획과 대조하는 것은 각 task를 지나온 쪽이 보기 어려운 각도다. 전달: `plan.md` 경로 · BASE SHA(`plan.md` `## Goal` 아래 `> BASE:` 줄의 값 — 커밋 제목으로 짐작하면 사이에 낀 커밋이 diff 범위를 틀어 놓는다) · HEAD SHA · `AGENTS.md` 경로 · 위 증거 대조 출력(또는 미실행 줄) · 전사 요약 경로(또는 미실행 줄) · 리뷰 시점에 순서가 아직 오지 않은 회차 끝 단계마다 `회차 끝 대기 — <남은 단계>` 줄(있을 때만 — 4번이 돌릴 명령(`AGENTS.md` 빌드·테스트·Lint/Format·검증 매핑)이 측정 방법인 Goal 기준 · 그 레포 `AGENTS.md` 가 4번 뒤에 두는 복원·정리 · plan 파일 커밋 · push — 리뷰어가 순서 전 단계를 미실행 BLOCKER 로 낸다(2026-11-20 Karina plan 11 — 예정된 dev 픽스처 복원)) · 플러그인 루트(`../../READONLY-SUBAGENTS.md`「플러그인 루트」).
  - **경량 plan(`## Goal` 에 `> 경량:` 줄 — 서식 `../../plan/references/light-plan.md`「경량 plan」)이고 `git diff --name-only <BASE>..HEAD` 에서 경로가 전부 문서·이미지인 `[면제 ①]` Files 줄의 경로를 뺀 수(셈법은 `../../plan/references/light-plan.md`「경량 계획」 의 「파일 2개 이하」)가 3파일 미만이면 부르지 않는다 — 대신 이 세션이 `../../../agents/completion-reviewer.md`「검사 항목」 다섯(요구 ↔ 산출물 · task 완료 상태의 진실성 · Goal 성공 기준(측정 방법 대조 — 측정은 4번) · Deferred 처리 · 함정 기록)을 체크리스트로 재고, 항목마다 `<항목> — <참|거짓|회차 끝 대기> — <근거 명령·출력>` 줄을 최종 보고에 싣는다(「회차 끝 대기」 는 위 전달물과 같은 기준이고 그 단계의 출력으로 닫는다). 「요구 ↔ 산출물」 항목은 그 줄 대신 `report-format.md`「보고 형식」 의 `요구 대조:` 줄을 요구 항목마다 쓴다** — 1~2파일 회차(같은 셈법)에 리뷰어 한 번(수 M 토큰)을 줄이되, 한 항목이라도 빠지면 그 항목을 아무도 재지 않는다. 위 증거 대조는 그대로 돌고, 거짓이 남으면 고친 뒤 다시 잰다. 같은 셈법으로 3파일 이상이면 계획 시점 실측이 틀린 것이라 부른다.
- **리뷰어는 백그라운드로 띄우고, 완료 통지를 기다리는 동안 레포 파일을 고치지 않는 일(4번 명령 실행·출력 판독 · `report-format.md` Read · 최종 보고 초안)만 한다 — 4번의 Progress Log 쓰기(`4번 검증:` clean 줄 · 화면 경로 줄)는 리뷰 완료 통지와 호출 뒤 작업 트리 확인이 끝난 뒤에 한다** — plan 파일을 추적하는 레포에서는 그 쓰기가 호출 뒤 확인에 리뷰어 탓으로 잡힌다. 리뷰 대기 중 다른 파일을 만지면 다음 커밋이 그것을 함께 담아 커밋 단위가 엉킨다(하니스 레포 관측 2026-09-02 — 한 회차에 3회).
- **결과를 받아 판정한 뒤에 완료 선언으로 간다** — 호출만 하고 다음으로 넘어가면 리뷰가 없는 것과 같다.
- **BLOCKER·MAJOR 는 고친다 — 다시 호출하는 것은 등급과 관계없이 그 수정이 동작·절차(명령·판정·단계·실행 경로)를 바꿨을 때뿐이다. 문구만 고친 수정(오탈자·표현·인용 교정)과 고친 지적의 해소 확인은 지적의 명령을 다시 돌려 보이고 수정 커밋 본문에 `해소 — <지적 요지> — <재실행 출력 요지>` 를 적으며, 재호출하면 그 줄들도 전달물에 더한다 — 일반·중계 모드 공통이다** — 지적이 남은 산출물을 통과시키면 그 결함이 다음 회차로 가고, 해소 확인만을 위한 재호출은 마무리까지 쌓인 컨텍스트를 통째로 다시 읽어 계획 리뷰보다 비싸다(pstack autopilot-full *"a minor fix gets a single verifier at the new head, and a wording-only change gets none"* — `https://github.com/cursor/plugins/blob/ae5650febf4320793844c12c4adaa937f417f8da/pstack/skills/poteto-mode/playbooks/autopilot-full.md`). MINOR 는 아래 「필터 패스」가 가른다.
  - **완료 리뷰 지적은 고치기 전에 지적의 명령을 다시 돌린다 — 같은 실패가 나오면 고치고, 나오지 않으면 재실행 출력으로 기각한다(`기각 — <요지> — <재실행 명령·출력 요지>`)** — 리뷰어는 diff 와 문서만 보고 호출 사슬 전체를 보지 못해, 「여기 X 가 올 수 있다」 같은 가정 경로를 그대로 고치면 증거 없는 가드가 늘고 범위가 번진다. 증명 책임을 지적한 쪽에 두는 것은 pstack interrogate 의 *"A finding survives only when a run proves it."* · *"Keep a finding when the output shows the failure and the failure breaks the intent. Drop the rest."* 를 들인 것이다(`https://github.com/cursor/plugins/blob/ae5650febf4320793844c12c4adaa937f417f8da/pstack/skills/interrogate/SKILL.md`).
  - **근거에 실패를 보이는 출력이 없는 완료 리뷰 BLOCKER·MAJOR(줄이 있다는 출력·파일:라인 인용뿐인 것)는 MINOR 로 내려 아래 「필터 패스」로 보낸다 — 보안 지적·증거 누락 지적·요구 미이행 지적·남은 이슈 위장 지적만 예외로 등급을 유지한다** — 전달한 검증 출력·커밋 본문의 실패 출력 인용은 실패를 보이는 출력이다. 위장 지적은 그 Deferred 항목 원문이 근거이고 ⓐ(고쳐 지우기)로만 닫는다.
    - **요구 미이행 지적은 근거가 `> 요구:`·`## Goal` 항목에 대응하는 diff 가 0건임을 보이는 명령 출력(`git diff --stat BASE..HEAD -- <그 항목의 Files>` 가 비었다 · 그 항목의 앵커 grep 이 0건이다)인 것이다 — 그 출력이 실패를 보이는 출력이라 강등하지 않고 ⓐ(이행)나 사용자 답이 있는 요구 축소로만 닫는다** — 만들지 않은 것은 재현할 실패가 없어, 재현을 요구하면 빠진 요구가 MINOR 로 내려가 버려진다.
    - **증거 누락 지적은 근거가 ⓐ 증거 대조(`check-plan -Base`)의 위반 코드 출력 ⓑ 있어야 할 기록(검증 결과·RED·화면 판정·옛 표현 grep 0건 등)이 0건임을 보이는 명령 출력 ⓒ 기존 케이스 단언·검사 설정·Acceptance·Goal 기준을 느슨하게 한 diff 인 것이다 — 그 출력 자체가 실패를 보이는 출력이라 강등하지 않고, 필터 패스 ⓑ 로 버리지 않으며 ⓐ(보충 증거·재검증·원복)로만 닫는다** — 이 지적은 원래 재현할 실패가 없는 꼴이라, 재현을 요구하면 「판정 없이 확인함」(`screen-scenarios.md`「완료 리뷰 대조」 의 BLOCKER) 같은 누락이 MINOR 로 내려가 버려진다. 이 둘(재실행·강등)은 완료 리뷰에만 걸린다 — `plan-reviewer` 는 명령을 돌리지 못해 아래 기준 넷만 쓴다.
  - **계획 리뷰 지적과 재현된 완료 리뷰 지적은 반증 출력이 있는 오탐만 기각한다.** 기준은 넷이다 — 원칙은 위 interrogate 인용이고, ⓐ~ⓓ 세부는 karina 기준이다(출처였던 interrogate 참조 문서는 upstream `ab1f702c` 에서 지워졌다).
    - ⓐ 「X 가 올 수 있다」 류는 호출부를 추적해 상위에서 이미 막혀 있음을 보이는 명령 출력(반증 출력)이 있으면 기각한다.
    - ⓑ 「나라면 다르게 했다」·조기 추상화 권유처럼 현재 방식의 구체적 문제를 보이지 않는 지적은 출력 없이 기각한다.
    - ⓒ 이번 회차가 쓰지 않은 코드를 겨누거나 레포 전체 관례와 같은 패턴을 지적하는 것(맥락 부족)은 그 관례를 보이는 출력으로 기각한다.
    - ⓓ 보안·정확성 지적은 반증 출력 없이는 기각하지 않는다 — 완료 리뷰의 정확성 지적은 재현된 것에만 걸린다.
  - **기각마다 `기각 — <지적 요지> — <반증 명령·출력 요지>` 줄을 최종 보고에 싣고, 재호출 때 그 줄들을 전달물에 더한다** — 리뷰어가 반증을 다시 대조할 수 있어야 같은 지적이 되풀이되지 않는다.
  - **같은 지적을 두 번째로 기각하게 되면 기각하지 않고 최종 보고 「승인 필요 항목」 에 사용자 판단으로 올리고(지적·반증·권장안), 그 지적으로는 다시 부르지 않는다** — 기각과 재지적이 오가는 것을 멈추는 상한이고, 둘이 갈린 판정은 사용자 판단이다.

## 전사 대조

`completion-reviewer` 가 전사 요약 경로를 받았을 때 이 절대로 본다. 출처는 pstack show-me-your-work 「Audit the log against the transcript」 다 — 고정 위치 `https://github.com/cursor/plugins/blob/ae5650febf4320793844c12c4adaa937f417f8da/pstack/skills/show-me-your-work/SKILL.md` · *"A fork, pivot, or abandoned approach that shaped the work but isn't logged is a gap. Add it."*

- **대조 범위는 요약의 마지막 plan 진입 표지 뒤에 오는 첫 implement 진입 표지 뒤다 — plan 표지가 없으면 첫 implement 표지 뒤, 둘 다 없으면 전체** — 표지는 `T: Skill karina:<이름>` 줄과 `<command-name>/karina:<이름>` 이 든 `U:` 줄이다. 그 앞의 인터뷰 결정은 plan Decisions·인터뷰 줄이 담고, 마지막 implement 표지에서 자르면 정지 뒤 재발동한 회차의 앞 구간이 빠진다.
- **지적 대상은 `A:` 줄의 갈림길 선택·방향 전환·버린 접근과 `T: Bash` 의 되돌림 명령(`git restore`·`git checkout --`·`git revert`·`git reset`) 가운데 Progress Log `판정:`·`판정(정정):` 줄이나 plan Decisions 에 짝이 없는 것이다** — plan task 를 그대로 수행한 단계·기계적 재시도·이미 판정 줄이 있는 것은 대상이 아니다. 판정 줄은 실행 세션만 쓰고 최종 보고가 그 줄을 옮겨 실으므로, 짝이 없는 결정은 리뷰도 보고도 지나지 않고 사라진다.
- **등급은 MINOR 이고, 근거 칸에 요약 줄 원문을 인용한다** — 산출물이 아니라 기록이 빠진 것이라 완료를 막지 않는다. 인용이 없으면 호출자가 그 갈림길을 찾지 못한다.
- **위 대조 범위 안에 `A: [한글 없음]` 줄이 있으면 그 줄을 인용해 MINOR 로 지적한다 — 요약 머리 `# 한글 없는 A:` 는 세션 전체 수라 판정에 쓰지 않는다** — 한 세션에서 회차가 여럿 돌면 앞 회차·plan 단계의 줄까지 세어 오탐한다. `../SKILL.md`「진행 중 사용자와의 소통」 의 「상태 메모·진행 안내도 한글로」 를 어긴 줄이고, 응답 언어 hook 은 영문 메모가 난 뒤의 다음 셸·쓰기 호출에 교정 줄을 실을 뿐이라 그 사이에 샌 줄은 이 사후 계수만 잰다. 호출자는 필터 패스 ⓑ 로 버린다(이미 나간 메모라 고칠 파일이 없다).
- **대조 범위 안 `SLOW: Bash` 줄에 같은 검증 명령이 2회 이상이거나 task 검증 출력에 경고·0 이 아닌 종료 코드가 있는데 Progress Log `도구 점검:`·`판정:` 줄에 그 처리(고친 커밋 · 대상이 아닌 근거)가 없으면 그 줄을 인용해 MINOR 로 지적한다** — 도구 점검 단계(위 「완료 순서」)를 건너뛴 회차를 잡는 자리이고, 호출자는 필터 패스 ⓐ 로 그 도구를 고친다.
- **호출자는 아래 필터 패스 ⓐ 로 빠진 판정 줄을 Progress Log 끝에 덧붙이고 줄 끝에 `(완료 리뷰 전사 대조)` 를 단다 — 앞 줄을 고쳐 쓰지 않는다** — *"Correct the log, not the story."* 사후에 붙였다는 표지가 있어야 그 자리에서 쓴 판정과 갈린다.

| ⓐ | **고친다** | 결함이고(실해가 아직 관측되지 않았어도 같다) 넘기는 둘·다른 종류의 세션(`deferred-rules.md`)에 들지 않는다 |
| ⓑ | **버린다** | 지시하는 액션이 파일 수정이 아니다(교훈·작성법·미착수 제안) — 실해가 관측되지 않았다는 것만으로는 버리지 않고, 증거 누락 지적(위 「절차」)은 여기로 오지 않는다 |

- **대장 등재는 종결로가 아니다.** 예외는 하나 — **넘기는 둘(또는 다른 종류의 세션)에 드는 것**이며, 그때만 `## Deferred / Follow-up` 에 둘 중 무엇인지와 함께 `[등재]` 로 적고 하한선 두 축을 함께 만족시킨다(`../../plan/references/deferred-rules.md`). **그 등재분은 위 「완료 순서」대로 리뷰가 끝난 뒤 대장으로 옮긴다** — 회차의 대장 이관은 리뷰 전에 이미 지나갔다. **결함이면 ⓐ다 — 결함인지 모르면 그 지적의 재현 명령을 1회 돌려 가른다(실패가 나오면 ⓐ, 나오지 않으면 ⓑ)** — 애매한 것을 대장에 올리면 대장이 늘고, 재지 않고 버리면 결함이 남는다(사용자 요청 2026-11-20 「남은 이슈가 없도록 모두 작업」). 실해 축은 넘기는 것을 대장에 올릴 때의 하한선에만 쓴다.
- **ⓑ로 버린 것은 `[미등재:<사유>]` 로 남기고, ⓐ로 고친 것은 항목을 지운다(기록은 `판정:` 줄과 커밋 본문)** — 버린 판정은 커밋 어디에도 남지 않아 지우면 다음 회차가 같은 것을 또 발견한다. 화면에는 내지 않는다(`report-format.md`「남은 이슈」).
- **필터 패스가 등재 문턱보다 먼저다** — 리뷰 소스의 지적은 여기서 먼저 갈리고, **걸러지지 않은 것만** `deferred-rules.md` 의 하한선을 통과한다. 순서가 반대면 리뷰가 대장의 최대 유입원이 된다.
- **이번 회차가 낸 흠을 다음 회차에 넘기는 것은 처리가 아니라 전가다** — ⓐ의 문턱을 낮게 잡는다.
- **같은 지적이 3회 연속이거나, 고칠 때마다 새 MINOR가 나서 라운드가 늘면 멈춘다** — 이것은 `../SKILL.md`「멈추는 넷 — 그리고 목록 밖의 넷」의 목록 밖 정지이고, 라운드는 「동일 원인 3회 실패」·「같은 수단을 3회 반복」처럼 3에서 센다.
  - **멈추기 전에 이 회차가 걷은 화면 가리기를 다시 덮는다 — `../../SCREEN-COVER.md`「언제 끄고 켜는가」**
- **리뷰어가 호출되지 않는 환경이면 그 사실을 최종 보고에 적고 진행한다** — 리뷰 부재를 통과로 적지 않는다.
- **plan 승인이 이 호출의 승인이다** — 리뷰 지점에서 사용자에게 묻지 않는다.
