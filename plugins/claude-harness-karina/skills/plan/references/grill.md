# 따지기

> `interview.md`「승인 제시」에서 사용자가 `G` 를 골랐을 때만 읽는다 — 다 쓴 `plan.md` 를 놓고, 모델이 묻지 않고 정한 것을 사용자와 끝까지 따지는 절차다. 질문 형식은 `interview.md`「2-2. 한 번에 한 질문, 추측을 붙여서」 를 그대로 쓰고 여기서 다시 쓰지 않는다.
> 외부 선례: mattpocock/skills `grilling` (`https://github.com/mattpocock/skills/blob/5beb35b040e3de97e54fa9e386d7e42d15c295c2/skills/productivity/grilling/SKILL.md`) — *"The session is done when the frontier is empty: every branch of the design tree visited, nothing left silently assumed."* 라운드 묶음 상한은 들이지 않았다(위키 결정 이력 2026-10-20 「인터뷰 질문 묶음」).

## 무엇을 따지는가

- **대상은 셋이다 — 승인 제시 `결정:` 의 `(근거로 정함)` 결정 · task 의 분해와 순서 · plan 이 깔고 있는 가정(`(추정)` 표기가 붙은 근거·잰 값 없이 적은 착수 기준선·Investigation Log 에 행이 없는 전제)** — 사용자가 따질 자리는 모델이 혼자 정한 쪽이다. 요구 인터뷰는 쓰기 전에 끝났고 `plan-reviewer` 는 실측 근거만 보므로, 혼자 정한 결정은 승인 화면 한 줄로만 지나간다.
- **`(사용자 답)` 결정은 다시 묻지 않는다** — 이미 사용자가 답한 것을 또 물으면 같은 결정을 두 번 내리게 한다. 사용자가 가지 목록을 보고 그것을 다시 열자고 하면 그때만 연다.
- **중계 모드(`relay-mode.md`「중계 모드」)에는 이 절차가 없다** — 사용자 화면이 없고, 그 승인은 `Y`/`E`/`N` 만 받는다.

## 절차

1. **가지 목록을 먼저 보인다** — 위 셋에서 고른 가지마다 한 줄로, 번호와 지금 plan 이 고른 답을 붙인다. 사용자가 목록에서 빼거나 더할 수 있다.

   ```
   따지기 — 가지 목록
     1. <결정·task·가정 요지> — 지금: <plan 이 고른 것> (근거: <Decisions 행·Log 행>)
     2. …
   ```

2. **가지를 라운드로 묻는다** — 형식·묶음 상한 3·가장 덜 확신하는 가정의 단독 라운드는 `interview.md` 2-2 그대로다. `GUESS:` 는 지금 plan 이 고른 답이 아니라 지금의 실제 판단이다 — 따지면서 생각이 바뀌었으면 바뀐 쪽을 낸다.
3. **답을 `plan.md` 에 반영한다** — 문답은 `> 요구:` 블록 아래에 `> 따지기 Q<N>: <질문> / 선택지: <이름들> / A: <답>` 으로 덧붙이고, 바뀐 결정은 `## Decisions` 근거 열에 `사용자 답(따지기)` 를 붙인다. 답이 Goal·Out of Scope·task 를 바꾸면 그 절도 고친다. 재호출된 리뷰어가 바뀐 절의 출처를 요구 블록에서 찾는다.
4. **고칠 때마다 `check-plan.ps1` 을 다시 돌린다** — 호출과 처리는 `../SKILL.md` Step 6 첫 불릿 그대로다.

## 종료 조건

- **가지 목록이 비면 끝난다 — 모든 가지가 답을 받았거나 사용자가 뺐을 때다. 기본 인터뷰의 「확신도가 세 라운드 연속 오르지 않으면 멈춘다」(`interview.md` 2-5)는 쓰지 않는다** — 가지를 끝까지 닫는 것이 이 절차의 목적이다.
- **사용자가 도중에 `Y`·`S`·`C`·`N` 으로 답하면 거기서 끝난다** — 남은 가지는 묻지 않는다. 단 `Y`·`S` 를 받았는데 아래 재호출이 남아 있으면 재호출을 마친 뒤 승인 제시를 다시 낸다 — 리뷰받지 않은 plan 이 그 답으로 승인되지 않게 한다.

## 끝난 뒤

- **task 나 acceptance 가 바뀌었으면 `plan-reviewer` 를 1회 다시 부른다 — 문구만 바뀐 답이면 부르지 않는다** — 리뷰받지 않은 plan 이 따지기 답으로 승인되지 않게 한다. 이 1회는 따지기 한 번마다 세고, `review-rounds.md`「리뷰 라운드」 의 3라운드 상한과 따로 센다. 재호출에서 나온 BLOCKER·MAJOR 는 고치고 다시 부르지 않으며, 승인 제시 `남은 리뷰 지적:` 에 등급 그대로 `(따지기 재검토 — 고침·재검토 안 함)` 으로 싣는다. 반증 출력이 있는 오탐은 `../../implement/references/final-review.md`「절차」 의 기각 기준대로 고치지 않고 기각해 같은 줄에 `(기각 — 반증 출력이 보인 사실)` 로 싣는다.
- **경량 계획이면 경량 네 조건(`interview.md`「경량 계획」)을 다시 잰다** — 그대로면 리뷰어를 부르지 않는다. 하나라도 깨지면 경량 표지를 지우고 일반 템플릿으로 다시 쓴 뒤, 일반 경로의 첫 리뷰로 `plan-reviewer` 를 부른다(`review-rounds.md`「리뷰 라운드」 의 3라운드 규칙 그대로). 전환할 때 Investigation Log 가 드러낸 연관 수정이 있으면 후보 라운드를 열고, 없으면 `> 후보 라운드: 후보 없음` 을 적는다.
- **승인 제시를 다시 낸다 — `[G]` 도 다시 둔다** — 따지기 답이 새 가지를 만들 수 있다. 따지기로 정한 결정은 `결정:` 에 `(사용자 답)` 으로 싣는다.
