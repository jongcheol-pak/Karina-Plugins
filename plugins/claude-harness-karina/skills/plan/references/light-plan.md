# 경량 계획

> `plan/SKILL.md` Step 3 끝(후보 라운드를 열지 않는 경로)과 Step 6(리뷰어 생략)이 가리킨다. 실측이 네 조건을 채운 작은 변경의 진입 판정(「경량 계획」)과 plan 서식(「경량 plan」)이 여기 모인다 — 경량 경로는 `interview.md`·`plan-template.md` 전문을 읽지 않고 이 파일과 두 문서의 지목된 절만 읽는다.

## 경량 계획

**Step 3 실측이 아래 네 조건을 모두 채우면 짧은 plan 으로 계획하고 승인 1회로 끝낸다.** 1~2파일 변경(실행 경로를 바꾸지 않는 문서·이미지는 세지 않는다)에도 후보 라운드·`plan-reviewer`·전체 템플릿이 그대로 돌면 계획 비용이 변경보다 커진다. pstack multi-phase-plan 1단계의 *"When the change is one or two files with an obvious approach, skip the plan. Say so and stop."* 를 들이되, 계획을 건너뛰지 않고 줄인다 — 모델 혼자 판정해 게이트를 여는 경로를 만들지 않기 위해서다. `karina:karina-systematic-debugging` 의 「경량 경로」(원인이 확정된 버그의 단계 축약)와는 다른 절차다.

| 조건 | 무엇을 재는가 |
|---|---|
| 파일 2개 이하 | task `Files` 줄의 백틱 경로 합집합 — 케이스 파일을 포함하고, 줄의 첫 `[면제` 뒤 경로는 세지 않는다. `[면제 ①]` 줄은 그 앞 경로가 전부 문서·이미지(`.md .png .jpg .jpeg .gif .svg .webp .ico`)면 통째로 세지 않는다(문서 제외) — 코드가 하나라도 섞이면 다 센다 |
| 새 공개 표면 없음 | 새 파일·공개 API·명령·설정 키를 만들지 않고, task 하위 항목이 기존 파일에 새 절(`##`·`###`)을 만든다고 적지 않았고, 경계를 넘는 재구성(`plan-template.md`「작업 단계」)도 없다(`- **구조**:` 줄이 필요 없다) |
| 승인 필요 없음 | `## 승인 필요 항목` 에 올릴 것이 없다 |
| DB·외부 없음 | DB 변경·외부 호출·환경변수·새 패키지 소스가 없다 |

- **조건마다 Investigation Log 에 실측 행을 남긴다** — 승인 화면의 값이 그 행에서 온다. 잰 행이 없는 조건은 채운 것으로 치지 않는다.
- **사용자가 이 세션에서 직접 부른 `karina:plan` 만 경량을 탄다** — 중계 모드가 타지 않는 근거는 `relay-mode.md`「중계 모드」가 정본이다.
- **후보 라운드 후보(함께 고칠 곳·대장 겹침·설계 결함·추가 기능)가 하나라도 나오면 경량을 버리고 일반 경로로 간다** — 라운드를 건너뛰면서 후보를 숨기면 연관 수정이 완료 보고에서야 나온다.
- **단 둘은 후보로 세지 않고 문서 동기화로 처리한다 — 고칠 대상이 문서·이미지뿐인 함께 고칠 곳(이 변경을 서술하는 문서)과, 처리가 대장 항목 문면만 고치는 대장 겹침이다** — 문서 task 로 자동 포함하고(파일 수는 「문서 제외」로 센다) 승인 제시에 `문서 동기화: <경로> · …` 한 줄로 보인다. 물을 갈림길이 없는 문서 맞춤 때문에 코드 2파일 변경이 일반 경로(리뷰어 2라운드)로 가던 것을 막는다(Karina 2026-11-13). 코드가 섞인 함께 고칠 곳·설계 결함·추가 기능은 그대로 일반 경로다. 대장 문면만 고치면 `▶ 현행 잔량` 줄은 바꾸지 않는다.
- **건너뛰는 것은 셋이다** — 후보 라운드 · `plan-reviewer` 호출 · 실측 뒤에 드러난 갈림길 없는 확인 질문(`interview.md` 2-3 기준 — 경량에서는 묻지 않고 `## Decisions` 에 근거와 함께 적는다). 인터뷰(`interview.md` 2-1~2-5)와 재진술은 그대로다 — 재진술 동의는 승인 제시가 겸한다.
- **건너뛰지 않는 것** — `check-plan`(`../SKILL.md` Step 6 첫 불릿 — 경량 조건 셋을 기계로 잰다 · `check-plan 미실행` 이면 셋이 재지지 않았으니 경량 표지를 지우고 일반 경로로 간다) · 승인 표지(`> BASE:`·`> 승인:`) · 승인 직후 `karina:implement` 호출. plan 서식은 아래 「경량 plan」 이다.
- **승인 제시는 `interview.md`「승인 제시」 서식에 아래 두 줄을 더한다** — 사용자의 승인이 경량 진입의 확인을 겸한다.

  ```
  경량 계획: 파일 <N>(<경로> · <경로>) · 문서 제외 <M>(<경로> · …) · 새 공개 표면 없음 · 승인 필요 없음 · DB/외부 없음 — 실측
  후보 없음 — 확인 범위: <무엇을 쟀는가 한 구>
  문서 동기화: <경로> · <경로> | 없음
  ```

  `남은 리뷰 지적:` 줄은 `계획 리뷰 생략(경량)` 으로 적는다. 사용자가 `E` 로 일반 경로를 요청하면 경량 표지를 지우고 일반 템플릿으로 다시 쓴다.
- **구현 중 변경이 파일 3개 이상(위 「파일 2개 이하」 와 같은 셈법)으로 번지면 `karina:implement` 는 멈추지 않고 `판정:` 줄로 남긴다 — 완료 리뷰가 실제 diff 규모로 `completion-reviewer` 를 부른다(`../../implement/references/final-review.md`「절차」)** — 계획 시점 실측이 틀린 것은 정지가 아니라 리뷰로 잡는다. 승인이 필요한 변경이 새로 생기면 경량과 무관하게 `../../implement/references/loop-exceptions.md`「plan 밖 변경」 대로 멈춘다.

## 경량 plan

**경량 계획(위 「경량 계획」)으로 정한 plan 은 `plan-template.md`「템플릿」 에서 두 절을 빼고 Goal 머리에 한 줄을 더한다.** 진입 판정은 그 절이 정본이고, 여기는 서식만 담는다.

- **`## Out of Scope` 와 `## 검증 방법` 을 뺀다** — 각 task 의 `- **검증**:` 줄이 검증 방법 표를 대신한다. 범위 밖으로 둘 것이 있으면 경량 대상이 아니다.
- **Goal 머리 넷(`> BASE:`·`> 승인:`·`> 시작:`·`> 완료:`) 아래에 `> 경량: 파일 <N> (<경로> · <경로>) · 문서 제외 <M> (<경로> · …) · 새 공개 표면 없음 · 승인 필요 없음 · DB/외부 없음` 줄을 둔다(뺀 것이 없으면 `문서 제외 0`)** — `check-plan` 과 완료 리뷰(`../../implement/references/final-review.md`「절차」)가 이 줄로 경량 plan 을 가른다. 값은 Investigation Log 의 실측 행에서 옮긴다.
- **Investigation Log 에 「서술 문서 자리」 행을 둔다 — 바꾸는 이름·문면을 `git grep -l -F` 로 찾아 그 문서들을 출력 요지에 적는다. 이 행이 없으면 경량 진입 조건을 채운 것으로 치지 않는다** — 위 「경량 계획」 의 문서 동기화가 이 행의 경로를 task 로 넣는다. 재지 않으면 서술 문서 누락이 완료 리뷰에서야 나온다.
- **나머지는 그대로다** — `> 요구:` · Goal 문단과 성공 기준 표 · Investigation Log · task 블록 서식(하위 항목·Files·Acceptance·검증) · `## Deferred / Follow-up`(없으면 「없음」). Decisions 는 실측 뒤 스스로 정한 것이 있을 때만 둔다.
- **`check-plan` 이 경량 조건 중 기계로 갈리는 셋(Files 경로 3개 이상 — 셈법은 위 「경량 계획」 의 「파일 2개 이하」 행 · `- **구조**:` 줄 · `## 승인 필요 항목` 절)과 중계 원문을 위반으로 낸다** — 코드 뜻은 스크립트 머리 주석이 정본이다. 위반이 나면 경량 표지를 지우고 일반 템플릿으로 다시 쓴다. 경량 plan 의 Files 줄 백틱에는 경로만 쓴다.
