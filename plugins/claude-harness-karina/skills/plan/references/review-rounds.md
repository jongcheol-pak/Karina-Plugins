# plan 리뷰 라운드 (`karina:plan` Step 6)

> `../SKILL.md` Step 6 이 이 파일을 연다 — `check-plan.ps1` 결과를 처리할 때(「check-plan 처리」)와 `plan-reviewer` 지적을 받았을 때(「리뷰 라운드」). 따지기 뒤 재호출은 `grill.md`「끝난 뒤」, 중계 모드 예외는 `relay-mode.md`「중계 모드」 다.

## check-plan 처리

- **exit 1 이면 출력 줄마다 고치고 다시 돌려 exit 0 을 보고, 오탐이면 Investigation Log 에 `check-plan 오탐` 행으로, 같은 코드가 3회 연속 남으면 `check-plan 미해소 — <코드>` 행으로 적고 넘어간다. exit 0·1 이 아니면(exit 2 · pwsh 부재·기동 실패 포함) 또는 출력이 없으면 `check-plan 미실행 — <사유>` 줄을(경량 계획이면 리뷰어가 없으니 먼저 `light-plan.md`「경량 계획」 대로 일반 경로로 바꾼다), `skip` 줄이 있으면 그 줄을, 오탐·미해소 행이 있으면 그 행을 리뷰어 전달물에 싣는다. `plan-check` 위반은 레포가 `AGENTS.md` 에 선언한 계획 검사가 실패한 것이라 줄 끝 파일(임시 폴더 `karina-plugin\scratch\`)을 읽어 plan 을 고친다** — 문자열로 갈리는 판정은 결정적 검사가 먼저 걸러야 리뷰 라운드가 판단에만 쓰인다.

## 리뷰 라운드

- **`plan-reviewer` 는 task Files 경로 합이 4 이상이거나 `## 승인 필요 항목` 에 항목이 있을 때만 부른다(경량 계획은 `light-plan.md`「경량 계획」 대로 늘 생략) — 경로 합은 `- **Files**:` 줄 백틱 경로의 합집합이고 줄의 첫 `[면제` 뒤는 세지 않으며 문서도 센다. 센 명령과 값을 Investigation Log 행으로 남기고, 부르지 않으면 승인 제시 `남은 리뷰 지적:` 에 `계획 리뷰 생략(경로 <N> · 승인 필요 없음)` 으로 적는다** — 작은 계획은 `check-plan` 과 승인 화면이 리뷰어 몫 대부분을 덮고, 리뷰 한 번이 수 분이다(사용자 답 2026-11-14 「4파일 이상·승인 항목 있을 때」). 하니스처럼 지침 문서가 실행 자산인 레포에서 문서를 빼면 거의 모든 계획이 빠진다.
- **재호출은 델타 검사다 — 이 절의 라운드 2·3, `grill.md`「끝난 뒤」, `relay-mode.md`「중계 모드」의 재호출 모두 같다** — 바뀌지 않은 절은 앞 라운드가 이미 봤다(2026-11-14 실측 — 14일 재호출 51회 중앙값 2.7분·도구 호출 24회가 전체를 다시 돌았다).
  - **스냅숏은 `%TEMP%\karina-plugin\scratch\plan-review-<레포 폴더명>.md` 하나이고, 부를 때마다 순서는 「(재호출이면) `git diff --no-index -U3 -- <스냅숏> plan.md` 를 낸다 → `cp plan.md <스냅숏>` 으로 갱신한다 → 부른다」 다 — 첫 호출은 스냅숏만 남긴다** — 스냅숏을 먼저 갱신하면 diff 가 빈다. diff 는 차이가 있으면 exit 1 이 정상이다. `cp` 는 `plan.md` 를 읽는 복사라 `../SKILL.md` Step 5 의 쓰기 금지 대상이 아니다.
  - **재호출 전달물은 직전 지적 목록과 그 diff 출력이고, diff 는 프롬프트 본문에 싣는다** — 파일로 넘기면 그 파일도 다시 가리키는 임시 파일이 된다.
  - **리뷰어가 보는 델타 범위는 지적 해소 · 바뀐 줄 · 그 줄이 속한 task · 그 task 를 가리키는 Goal 행·Decisions 다. 바뀐 줄이 task 밖이면 — 요구·따지기 문답 줄·Decisions 행은 그것을 인용·구현하는 task·Goal 행, Log 행은 그 행을 근거로 삼는 task 를 범위에 넣는다** — 따지기 답은 문답 줄과 Decisions 로 들어가(`grill.md`「절차」 3번) 속한 task 가 없다.
  - **스냅숏이 없거나(압축·재개로 잃음) diff 가 비면 diff 없이 부르고, 리뷰어는 전체를 본다** — 실패 경로를 기존 동작으로 되돌린다.

- **BLOCKER·MAJOR는 plan을 고쳐 해소하되, 다시 호출하는 것은 BLOCKER 가 있었을 때뿐이다 — MAJOR 수정은 다시 부르지 않고 승인 제시 `남은 리뷰 지적:` 에 `(고침·재검토 안 함)` 으로 싣는다 · 반증 출력이 있는 오탐은 `../../implement/references/final-review.md`「절차」 의 기각 기준대로 기각해 승인 제시 `남은 리뷰 지적:` 에 싣고, 기각한 BLOCKER 는 3라운드 호출 조건에 세지 않으며, 같은 지적의 두 번째 기각은 기각 대신 원래 등급으로 싣는다** — 지적이 남은 계획을 승인받으면 그 결함이 구현 중에 드러난다. **MINOR는 처방이 정해져 있으면 고치고, 아니면 버린다 — 대장 등재는 종결로가 아니다** — 구현 전이라 실해가 원리상 관측되지 않아, 완료 리뷰의 「필터 패스」 실해 축을 쓰면 MINOR 가 전부 버려진다. (중계 모드 예외는 `relay-mode.md`「중계 모드」)
- **리뷰는 3라운드가 상한이고, 다음 라운드를 부르는 조건은 위 불릿 하나다. 같은 지적이 3회 연속이거나 3라운드째에도 BLOCKER·MAJOR 가 남으면 고치기를 멈추고 남은 지적을 승인 제시에 싣는다** — 매 라운드 조금씩 나아지는 것은 실패로 집계되지 않아 「동일 원인 3회」에 걸리지 않고, 남은 지적을 숨기면 승인하는 쪽이 그것을 모른다. 라운드 하나가 리뷰어 호출 한 번의 비용이라 다음 라운드는 BLOCKER 가 있었을 때로 한정하고, 재검토 없이 고친 것도 숨기지 않는다. 따지기 뒤 재호출은 이 상한과 따로 센다(`grill.md`「끝난 뒤」).
- **지적을 고치는 `plan.md` 수정은 Edit(전체 교체는 Write)로만 한다 — 여러 곳이어도 같다** — `sed`·python 쓰기는 `guard-bash` 가 막고, 지적 반영은 자리마다 문면이 달라 기계 치환이 맞지 않는다(`../SKILL.md` Step 5).
