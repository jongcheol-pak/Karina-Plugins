# Plan Draft

사용자가 `/karina:plan-draft` 로 부를 때만 돈다. 루트 `plan.md` 는 레포에 하나라, 다른 세션이 그 파일로 작업 중일 때 새 계획을 세우면 진행 중인 plan 을 덮어쓴다. 이 스킬은 계획을 초안 파일로 따로 두었다가, 그 충돌이 없을 때 `plan.md` 로 올린다.

**계획 절차는 여기 두지 않는다** — 인터뷰·실측·리뷰·승인은 `karina:plan` 이 그 스킬의 「초안 모드」·「진행 모드」(`../plan/references/draft-mode.md`)로 한다. 이 스킬은 초안을 고르고, `plan.md` 가 사용 중인지 가르고, `karina:plan` 에 넘길 프롬프트를 만든다.

## 경로

- **초안 폴더는 작업 디렉터리 루트의 `plans/drafts/` 이고, 진행 판정의 대상은 같은 루트의 `plan.md` 다** — 하니스 hook 이 plan 을 찾는 자리와 같다.

## 진행

1. **인자가 있으면 새 초안이다** — `karina:plan` 을 Skill 도구로 부르고 args 를 `[plan-draft 초안]` 한 줄 + 사용자의 요청 원문으로 넘긴다. 그 뒤는 `karina:plan` 이 끝낸다.
2. **인자가 없으면 초안을 센다** — `plans/drafts/*.md` 가
   - 0개면 「초안 없음 — `/karina:plan-draft <요청>` 으로 만든다」 한 줄을 내고 끝낸다.
   - 1개면 목록 없이 3으로 간다.
   - 2개 이상이면 번호 목록을 내고 고르게 한다. 줄마다 제목(`# plan — ` 뒤) · 작성일 · 작성 이후 커밋 수다. 커밋 수는 초안 Goal 의 `> 초안 작성:` 줄 HEAD 로 `git rev-list --count <HEAD>..HEAD` 를 돌린 값이다. 그 HEAD 가 레포에 없으면(`git cat-file -e <HEAD>` 실패) `?` 로 적는다.
3. **고른 초안을 보인다** — 목표(Goal 문단 첫 1~2문장) · task 줄(`### T<N>.` 제목) · 작성일과 작성 이후 커밋 수 · 경로를 보인다. 그다음 묻는다.

   ```
   [P] 진행 / [E] 수정 / [D] 삭제 / [N] 취소
   ```

4. **진행(`P`)**
   - **먼저 `plan.md` 가 사용 중인지 가른다.** 사용 중이란 파일이 있고, `(?m)^\s*([-*+]|\d+[.)])\s*\[[ /]\]` 가 하나 이상이며, `^> 완료: [0-9]{4}-` 줄이 없는 것이다. `[/]` 와 번호 목록도 센다 — 진행 중인 plan 은 남은 task 가 전부 `[/]` 일 수 있다.
   - **사용 중이면 옮기지 않고 묻는다.**

     ```
     plan.md 에 다른 작업이 진행 중입니다 — <plan.md 제목> · 미완료 task <N>개
     [W] 새 worktree 에서 진행 / [L] 나중에 / [O] 덮어쓰기
     ```

     - `W`: 세 단계로 한다.
       1. `git worktree add <경로> -b karina/<초안 slug>` 를 안내하고, 만든 뒤 알려 달라고 한다.
       2. 사용자가 답하면 `git worktree list` 로 그 경로를 확인하고, 초안을 그 worktree 의 `plans/drafts/` 에 같은 이름으로 Write 한다. 그 worktree 에서 다시 읽어 내용이 같은지 본 뒤 원본을 지운다. 초안은 한 곳에만 둔다.
       3. 「그 worktree 에서 새 세션을 열고 `/karina:plan-draft` 를 부른다」를 안내하고 끝낸다.

       무시 규칙은 `.git/info/exclude` 라 linked worktree 에도 걸린다.
     - `L`: 아무것도 바꾸지 않고 끝낸다.
     - `O`: `plan.md` 를 `../TEMP-FILES.md` 의 `backup\` 에 그 이름 규칙으로 백업하고 그 경로를 보인 뒤 아래로 간다. 진행 중인 다른 세션의 plan 이라 되돌릴 수단을 남긴다.
   - **사용 중이 아니면(없음·완료) 프롬프트를 만들어 `karina:plan` 을 부른다.**
     - 작성 이후 바뀐 파일: 초안 task `- **Files**:` 줄의 백틱 경로와 `git diff --name-only <작성 HEAD>..HEAD` 의 교집합이다. 작성 HEAD 가 없으면 「작성 HEAD 를 찾을 수 없음 — 전부 다시 잰다」로 적는다.
     - args 형식은 아래와 같고, 그 뒤는 `karina:plan` 이 다시 실측·리뷰해 승인을 받는다. 승인되면 초안을 지우고, 중단하면 초안이 남는다.

       ```
       [plan-draft 진행] <초안 경로>
       원문 요구: <초안 `> 요구:` 줄과 문답 줄 그대로>
       초안 작성: <날짜> · HEAD <sha> · 이후 커밋 <N>개
       작성 이후 바뀐 파일: <경로 목록 | 없음>
       초안 Goal: <Goal 문단>
       초안 Decisions: <표의 결정 열을 한 줄씩>
       초안 task: <T<N>. 제목과 Files 줄>
       ```

5. **수정(`E`)** — 무엇을 바꿀지 묻는다. 답을 받으면 `karina:plan` 을 부르고, args 를 다음 셋으로 넘긴다: `[plan-draft 초안]` 한 줄, 둘째 줄 초안 경로, 셋째 줄부터 수정 요청. 기존 초안의 백업과 되돌리기는 `karina:plan` 의 초안 모드가 한다.
6. **삭제(`D`)** — 경로와 제목을 보이고 「지우면 되돌릴 수 없다(git 밖 파일)」와 함께 한 번 더 묻는다. 예이면 지운다.

## 하지 않는 것

- **`plan.md` 를 직접 쓰지 않는다** — 쓰는 것은 진행 모드의 `karina:plan` 이다. 이 스킬이 쓰면 다시 실측·리뷰하지 않은 계획이 승인본 자리에 앉는다.
- **초안을 셸 리디렉션·`cp`·`sed` 로 쓰지 않는다** — Write·Edit 도구로만 쓴다. 도구 밖 쓰기는 잘림을 막지 못한다.
- **worktree 를 직접 만들지 않는다** — 명령 안내와 초안 복사까지다.
