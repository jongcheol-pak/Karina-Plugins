# 체인 끝 push (`karina:chain-plan`)

> `report.md`「인계 파일 정리」 의 정리 커밋 뒤, 보고 전에 이 파일을 연다.

## 체인 끝 push

**체인이 끝까지 성공했을 때(`report.md`「인계 파일 정리」 의 성공 조건과 같다) 그 정리 커밋 뒤, 보고 전에 1회 한다.** 워커는 push 하지 않아(`../../implement/references/push-flow.md`「기본 브랜치 push」 의 중계 모드) 이 단계가 없으면 체인 커밋이 로컬에만 남는다(2026-10-18 체인 커밋을 그 뒤 손으로 올려 제목 유형이 빠진 채 main 커밋이 됐다).

- **계획마다의 대상 레포 가운데 둘이 참인 레포마다 한다** — 대상 레포 경로가 세션 시작 때 주입된 위키 vault 경로와 같지 않다(vault 는 `karina:llm-wiki` 가 직접 push 한다) · 기본 브랜치에 없는 커밋이 있다(`git -C "<대상 레포 경로>" rev-list --count origin/<기본 브랜치>..HEAD` 가 0 이 아니다 — 원격이 없으면 참으로 치고 게이트 판정만 보고한다 — 기본 브랜치는 `../../implement/references/push-flow.md`「기본 브랜치 push」 판정이고, 기본 브랜치 미정이어도 게이트 판정만 보고한다(`push 건너뜀(기본 브랜치 미정)`)). 거짓인 레포는 보고의 `push:` 줄에 `건너뜀 — <거짓인 조건>` 으로 싣는다. 체인 브랜치가 기본 브랜치가 아니면 게이트·push 모두 하지 않고 `건너뜀 — 비기본 브랜치 · 병합 뒤 기본 브랜치에서 게이트를 거쳐 push` 다(`../../implement/references/local-gate.md`「대상과 범위」).
- **아래 「체인 끝 게이트」 게이트를 거쳐 `push-flow.md`「기본 브랜치 push」 의 push 를 하고 `push:` 줄에 `게이트 <판정> · push <결과>` 를 싣는다** — 체인 끝 push 가 그 레포의 회차 끝 push 다. git 명령은 모두 `git -C "<대상 레포 경로>"` 로 돈다(`push-flow.md`「기본 브랜치 push」 의 경로 규칙). 게이트 `FAIL` 은 `continuation.md`「체인 끝 게이트 FAIL」 이 받는다.
- **게이트 범위의 `git log --format=%B` 에 `화면: ` 으로 시작하는 줄(미촬영 줄 포함 — `../../implement/references/screen-scenarios.md`「화면 시나리오 실행」)이 있으면 게이트 본문 파일에 `## 화면` 절을 싣고, 같은 줄로 `## 검증` 에 `화면 시나리오:` 줄을 싣는다(아래 「체인 끝 게이트」)** — 이 세션은 워커의 `plan.md` 를 읽지 않아 커밋 본문이 화면 task 를 찾는 유일한 자리이고, 이 절이 있어야 게이트의 화면 확인이 걸린다.
- **어느 단계든 실패하면 오류 원문을 보고의 `push:` 줄에 싣고 멈추지 않는다** — 체인은 이미 끝났고, 커밋은 로컬 기본 브랜치에 그대로 있다.

## 체인 끝 게이트

코디네이터가 `../../implement/references/local-gate.md`「회차 끝 게이트」 를 체인 끝 push 직전에 1회 돈다 — 사용자 답 「체인 끝 1회」. 코디네이터는 대상 레포 밖에서 돌 수 있어 git 명령은 모두 `git -C "<대상 레포 경로>"` 로 돈다. 다른 자리는 다섯이다 — 다섯째는 보고 자리로, `../../implement/references/local-gate.md`「보고」 의 `NOTES`·릴리즈 줄을 `report.md`「보고 서식」 의 코디네이터 출처 줄로 싣는다.

- **범위의 아래 끝은 원격이 없으면 체인 결정 파일(`chain-decisions.md`「결정 기록」)의 `- plan 1 · 부모 <sha>` 다 — 그 줄이 없으면(결정 파일 중간 유실 · 재개가 이어받지 못함) 범위를 짐작하지 않고 `push: 게이트 건너뜀 · push 보류(범위 아래 끝 없음)` 로 보고한다** — 코디네이터는 워커의 `plan.md` 를 읽지 않는다. 짐작한 아래 끝은 검증하지 않은 커밋을 범위 밖에 남긴다(사용자 답 「push 보류」).
- **화면 줄의 출처는 `git log --format=%B <범위>` 의 `화면: ` 으로 시작하는 줄이다 — `화면 시나리오:` 줄은 `../../implement/references/local-gate.md`「디버깅 단독」 과 같이 만들고, `· 변형:` 이하 마디(`chain-decisions.md`「결정 기록」)는 그 줄에 싣지 않는다** — 체인 끝 push 가 게이트 본문 파일의 화면 절을 채우는 자리와 같다(위 「체인 끝 push」).
- **게이트 완화 서명과 화면 확인은 코디네이터가 사용자에게 직접 받는다 — `../../implement/references/local-gate.md`「화면 게이트」 의 사용자 원문 기준 그대로다** — 코디네이터 판정·위임 답은 서명이 아니다.
- **FAIL 이면 코디네이터가 고치지 않는다 — `continuation.md`「체인 끝 게이트 FAIL」 대로 실패 파일이 속한 계획의 이어받기 워커가 고치고, 끝나면 직전 판정을 넘겨 게이트를 다시 돈다(최대 2회)** — 코디네이터는 파일을 고치지 않는다(`../SKILL.md`「하지 않는 것」). 판정 기록은 결정 파일에 `- 체인 끝 게이트 · <판정> · head <full SHA> · base <full SHA> · patch-id <값> · 출력 <파일>` 줄로 남긴다 — 레포 밖 파일을 코디네이터가 직접 써 작성자를 안다.
