# 체인 끝 push (`karina:chain-plan`)

> `report.md`「인계 파일 정리」 의 정리 커밋 뒤, 보고 전에 이 파일을 연다.

## 체인 끝 push

**체인이 끝까지 성공했을 때(`report.md`「인계 파일 정리」 의 성공 조건과 같다) 그 정리 커밋 뒤, 보고 전에 1회 한다.** 워커는 push 하지 않아(`../../implement/references/push-flow.md`「기본 브랜치 push」 의 중계 모드) 이 단계가 없으면 체인 커밋이 로컬에만 남는다(2026-10-18 체인 커밋을 그 뒤 손으로 올려 제목 유형이 빠진 채 main 커밋이 됐다).

- **계획마다의 대상 레포 가운데 둘이 참인 레포마다 한다** — 대상 레포 경로가 세션 시작 때 주입된 위키 vault 경로와 같지 않다(vault 는 `karina:llm-wiki` 가 직접 push 한다) · 기본 브랜치에 없는 커밋이 있다(`git -C "<대상 레포 경로>" rev-list --count origin/<기본 브랜치>..HEAD` 가 0 이 아니다 — 원격이 없으면 push 하지 않고 `건너뜀 — 원격 없음` 이다 · 기본 브랜치는 `../../implement/references/push-flow.md`「기본 브랜치 push」 판정이고, 기본 브랜치 미정이면 `건너뜀(기본 브랜치 미정)`). 거짓인 레포는 보고의 `push:` 줄에 `건너뜀 — <거짓인 조건>` 으로 싣는다. 체인 브랜치가 기본 브랜치가 아니면 push 하지 않고 `건너뜀 — 비기본 브랜치 · 병합 뒤 기본 브랜치에서 4번 검증을 거쳐 push` 다.
- **아래 「체인 끝 push 전 확인」 을 거쳐 `push-flow.md`「기본 브랜치 push」 의 push 를 하고 `push:` 줄에 `push <결과>` 를 싣는다** — 체인 끝 push 가 그 레포의 회차 끝 push 다. git 명령은 모두 `git -C "<대상 레포 경로>"` 로 돈다(`push-flow.md`「기본 브랜치 push」 의 경로 규칙). push 가 성공했고 그 레포 Release 가 릴리즈 발행을 지목하면 `push-flow.md`「push 전 확인」 의 릴리즈 승인 줄을 `report.md`「보고 서식」 의 `승인 필요 항목` 에 `체인 끝:` 을 붙여 싣는다.
- **어느 단계든 실패하면 오류 원문을 보고의 `push:` 줄에 싣고 멈추지 않는다** — 체인은 이미 끝났고, 커밋은 로컬 기본 브랜치에 그대로 있다.

## 체인 끝 push 전 확인

`../../implement/references/push-flow.md`「push 전 확인」 의 체인 판이다 — 코디네이터는 워커의 `plan.md`(4번 clean 줄)를 읽지 않으므로, 근거는 이 세션이 계획마다 돌린 코디네이터 검증(`continuation.md`「코디네이터 검증」)이다. 새 worktree 재빌드·서브에이전트 재검증·사용자 화면 확인 대기는 두지 않는다(사용자 답 「바로 push + 스크린샷 보고」 2026-11-14).

- **push 해도 되는 것은 셋이 모두 참일 때다 — ⓐ 마지막 계획(이어받기 포함)의 코디네이터 검증이 고른 명령마다 `pass`·`reused` 이고 그 안에 대상 레포 `AGENTS.md` Build·Test 가 들어 있다(마지막 계획이 병렬 그룹원이면 `parallel.md`「병합」 ⓓ 의 결과) ⓑ 그 검증의 HEAD..지금 HEAD 의 커밋이 인계 파일 정리 커밋뿐이다 ⓒ `git -C "<대상 레포 경로>" status --porcelain --untracked-files=no` 가 비었다** — 계획마다 코디네이터가 ③ 을 독립으로 이미 돌려, 같은 스위트를 체인 끝에 다시 돌 이유가 없다.
- **ⓐ 가 거짓이면(`건너뜀`·`미검증` 이 섞였거나 Build·Test 가 ③ 에 없었다) 이 세션이 그 자리에서 `AGENTS.md` Build·Test 를 `continuation.md`「코디네이터 검증」 의 래퍼 규칙(`run-verify.py` · 명령마다 스크립트 파일 · `--stamp`)으로 돌리고, 모두 `pass`·`reused` 면 push 한다. 실패·미검증이면 push 하지 않고 `push: 보류(<명령> <RESULT>)` 와 출력 꼬리를 싣는다** — 코디네이터는 파일을 고치지 않는다(`../SKILL.md`「하지 않는 것」). 고치는 것은 사용자가 그 계획부터 재개한 워커다.
- **ⓑ·ⓒ 가 거짓이면 push 하지 않고 `push: 보류(<거짓인 조건>)` 로 보고한다** — 코디네이터가 모르는 커밋·미커밋 변경은 아무도 검증하지 않았다.
- **화면 스크린샷은 워커 `--body` 의 `화면 확인:` 칸을 `report.md`「보고 서식」 의 `화면 증거:` 줄로 싣고 push 를 기다리지 않는다.**
