# 체인 승인 화면 (`karina:chain-plan`)

> `../SKILL.md` 「체인 승인」이 화면을 낼 때 이 파일을 연다 — 체인 시작(재개 포함)에 한 번 쓰고, 압축 뒤 복원은 화면을 다시 내지 않는다(`compaction.md`「압축 뒤 복원」).

## 체인 승인 화면

```
계획 체인 승인 — 계획 <총>개

plan 1: <무엇을 하는가 — 사용자 관점 2~3줄>
  성공의 모습: <재진술의 성공의 모습>
  범위 밖: <재진술의 범위 밖>
  제약조건: <재진술의 제약조건>
  바뀌는 영역: <실측의 바뀌는 파일 | 워커 실측 후 확정>
  승인 필요 항목: <실측의 승인 필요 후보 | 없음 | 워커 실측 후 확정>
  요청 밖 항목: <인터뷰에서 포함한 것 | 없음>
  DB 변경: <목록 | 없음> (근거: …)
  근거로 정한 것: 의존 <①> · 검증 <③> — 각 (근거: …)
  판정 원칙: <요청·규약에서 읽은 기준 (근거: …) | 없음 — 재진술 목표·제약과 워커 권장안>
  인계: <다음 계획에 넘길 것 | 없음>
plan 2: …

판정 범위: 사용자 몫 다섯(실행 시점 승인·사용자 답 뒤집기·요청 범위 변경·기존 것을 깨는 변경·뒤 계획이 전제로 쓰는 화면 갈림길) 밖은 코디네이터가 판정해 보고에 모은다 — 내부 API·설정 변경 포함
미답 시한: 30분 — 넘긴 답 뒤집기·범위 변경·전제 화면 질문은 이 시간 뒤 보수 기본값(`E: 미답 시한 <N>분` · 45분 이하 — `user-relay.md`「미답 기본값」)
대기 보호: <켜짐 | 꺼짐 — `wait-exit.md`「대기 보호」>
병렬: <그룹 · 동시 상한 · 체인 브랜치 | 없음 — `parallel.md`「병렬 그룹」>
끝: 체인 끝 게이트 뒤 기본 브랜치 push 하나 — `chain-end-push.md`「체인 끝 push」

[Y] 승인 (권장) / [E] 수정 요청 / [N] 중단
```

## 답 갈래

- **`E` 면 그 계획의 재진술·체크리스트·판정 원칙을 고쳐 다시 내고, `N` 이면 Run 을 만들지 않고 보고한 뒤 끝낸다.**
