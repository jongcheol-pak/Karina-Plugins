# No comments

> 출처는 Cursor pstack 의 no-comments 다 — 고정 위치 `https://github.com/cursor/plugins/blob/8b3326d99fd4b993cb33a24dad8af03175c642c5/pstack/skills/no-comments/SKILL.md`. Copyright (c) 2026 Lauren Tan · MIT(`https://github.com/cursor/plugins/blob/8b3326d99fd4b993cb33a24dad8af03175c642c5/pstack/LICENSE`).
>
> **원문과 다르게 한 것** — ① 리뷰어 `comment-reviewer` 는 읽기 전용이고 주석 삭제는 이 세션이 검수 뒤에 한다 ② 원문의 `/architect` 스케치 대신 이 스킬 안에서 설계를 보이고 승인받는다 ③ 커밋하지 않는다 — diff 모드는 사용자의 미커밋 변경 위에서 돌아, 커밋하면 그 변경이 함께 들어간다 ④ 남길 주석의 기준은 `../implement/references/code-style.md`「주석」 하나다 ⑤ 편집 전 빌드·테스트 기준선을 둔다.
> **들이지 않은 파일** — 없다(원문 폴더는 SKILL.md 하나). 리뷰어는 `../../agents/comment-reviewer.md` 로 번안했다.

사용자가 `/karina:no-comments [경로…]` 로 부를 때만 돈다. implement 가 고치는 hunk 의 주석 정리(`code-style.md`「주석」)를 대신하지 않는다 — 그것은 매 수정마다 돌고, 이 스킬은 사용자가 정한 범위를 따로 정리한다.

## 진행

1. **범위를 정한다**
   - **인자 경로가 있으면** 그 파일 전체다(폴더면 그 아래 추적·untracked 파일).
   - **없으면 diff 다** — base 는 `git symbolic-ref --short refs/remotes/origin/HEAD` 에서 `origin/` 을 뗀 로컬 브랜치, 실패하면 `main` 이다. 기준점은 `git merge-base <base> HEAD` 이고, 범위는 `git diff <merge-base>`(작업 트리 포함)의 hunk 에 `git ls-files --others --exclude-standard` 가 내는 새 파일 전체를 더한 것이다. base 끝과 비교하지 않는다 — 분기 뒤 base 에 쌓인 남의 커밋이 역방향 hunk 로 섞인다.
   - diff 는 스크래치 파일에 저장해 리뷰어에게 경로로 넘긴다. **범위가 비면 「정리할 범위 없음」을 보고하고 끝낸다.**
2. **기준선을 남긴다** — 그 레포 `AGENTS.md` 의 빌드·테스트를 편집 전에 한 번 돌려 실패 목록을 적어 둔다. 명령이 없으면 8번이 「미검증」이다. 기준선 없이 편집하면 원래 있던 실패가 이 스킬 탓으로 잡혀 맞는 편집까지 되돌리게 된다.
3. **`comment-reviewer` 를 이름으로 1회 부른다** — 입력은 범위 종류 · 파일 목록 또는 diff 파일 경로 · 레포 루트 · `code-style.md` 의 절대 경로(이 SKILL.md 폴더 기준 `../implement/references/code-style.md`)다.
4. **판정을 검수한다** — 리뷰어 표를 그대로 믿지 않는다.
   - **거부한다**: 범위 밖 행 · 예외(`code-style.md`「주석」)에 드는데 `삭제` 로 판정한 행 · 근거가 사실과 다른 `MUST KILL` · 의도적으로 남긴 코드를 결함으로 지목한 행.
   - **`유지` 는 바꿀 수 없는 외부 제약이라는 근거가 있을 때만 받는다** — 「IMPORTANT」「do not remove」류 유지·삭제 판정이 근거가 얇으면 그 심볼을 직접 읽고 `git log -S` 로 확인한다. 확인 뒤에도 유지 근거가 애매하면 삭제한다.
   - **리뷰어가 놓친 범위 안 억제 주석**(`eslint-disable`·`@ts-ignore`·`noqa` 등)을 찾아 같은 기준으로 더한다.
   - 거부가 있으면 거부 사유를 붙여 리뷰어를 1회 다시 부른다. **두 번째도 거부되는 행은 고치지 않고 열린 항목으로 보고에 남긴다.**
5. **주석을 지운다** — 받은 `삭제`·`MUST KILL`·`제약` 행의 주석을 Edit 로 지운다(부분 편집). 파일 전체를 다시 쓰지 않는다.
6. **사소한 `MUST KILL` 을 바로 고친다** — 셋만 해당한다: 죽은 경로 삭제 · 안 쓰는 파라미터 제거 · 우회 코드를 실제 API 호출로 교체. **수정과 그 호출부가 모두 범위 안 파일일 때만이다** — 하나라도 범위 밖으로 번지면 7번으로 넘긴다.
7. **남은 `MUST KILL` 과 `제약` 은 설계를 보이고 승인받는다**
   - 한 화면에 모아 보인다: 항목마다 무엇을 바꾸는가 · 고칠 파일 · 범위 밖으로 번지는가 · `제약` 이면 가장 싼 인코딩(타입·런타임 검사·테스트·린트).
   - 사용자가 고른 것만 구현한다 — 범위 안에서 근본 원인을 고치는 최소 수정이고, 이름 붙은 우회 코드는 모두 지운다. **증상 가드(조건 하나 더 거는 방어 코드)를 더하지 않는다.** `제약` 은 인코딩한 뒤에 주석이 지워진 상태가 된다.
   - 근본 원인이 범위 밖이면 범위 안의 최소 수정만 하고 나머지는 열린 항목으로 남긴다. 고르지 않은 항목도 열린 항목이다 — `제약` 주석은 인코딩하지 않아도 지운 채로 두고 「강제되지 않는 제약」으로 보고한다.
   - 사용자가 응답할 수 없는 실행(루프·예약)이면 이 단계의 구현을 건너뛰고 전부 열린 항목으로 남긴다.
8. **빌드·테스트를 다시 돌린다** — 2번 기준선에 없던 실패만 이 스킬의 편집 탓으로 본다. 원인 편집을 Edit 로 되돌리고 그 항목을 열린 항목으로 옮긴다. **`git checkout`·`git restore` 는 쓰지 않는다** — diff 모드에서는 사용자의 미커밋 변경까지 지운다. 기준선부터 있던 실패는 그대로 보고한다.
9. **보고한다**
   - 범위 · 지운 주석 수 · 리뷰어 재실행 여부 · 바로 고친 것 · 승인받아 고친 것과 인코딩 · 열린 항목(거부 2회 · 범위 밖 원인 · 고르지 않은 항목 · 강제되지 않는 제약) · 2번·8번 검증 출력 중 판정에 쓴 줄.
   - **지운 주석의 이유** — 리뷰어 `이력` 칸이 `없음` 인 행의 이유를 커밋 본문에 붙여 쓸 수 있는 문단으로 싣는다. 이력에 있는 이유는 옮기지 않는다 — 커밋 이력에서 되찾을 수 있다.

## 하지 않는 것

- **커밋·push 하지 않는다** — 커밋은 사용자가 위 문단과 함께 한다.
- **범위 밖 파일을 고치지 않는다** — 범위는 1번이 정한 파일과 hunk 다.
- **implement 의 「hunk 밖의 주석은 건드리지 않는다」 를 바꾸지 않는다** — 그 규칙은 implement·디버깅이 코드를 고칠 때의 범위이고, 이 스킬의 범위는 사용자가 인자로 정한다.
