# doc 블록 주인 이동 차단 판정 근거

> `guard-harness.ps1` 이 dot-source 하는 편집 게이트(`guard-doc-owner.ps1`)의 판정 근거다. doc 블록과 그 블록이 설명하던 항목 사이에 새 항목을 끼워, 앞 항목이 doc 을 잃고 새 항목이 남의 doc 을 물려받는 편집을 막는다.

## §1 왜 막는가

**빌드·린트·rustdoc 어느 것도 이 실수를 잡지 못한다.** doc 이 다른 항목으로 넘어가도 문법은 그대로라 컴파일이 통과한다. Karina 레포 `docs/conventions.md` 는 2026-09-06 부터 이 함정을 적어 두었고 관측이 열두 건을 넘었다. 처방(「끼울 자리 바로 위가 `///` 면 앞 항목 본문 끝 뒤로 옮긴다」·「앵커는 doc 블록의 첫 줄로」)도 문서에 있었다. 그런데도 2026-11-11~12 Karina 체인(plan 4~11)에서 이름이 드러난 것만 24건이 다시 났다. 대부분 Edit 의 `old_string` 앵커를 `fn`·`#[test]`·`pub fn`·`const` 줄로 잡고, `new_string` 을 「새 항목 + 앵커」로 쓴 꼴이었다. 잡은 것은 회차 끝 `doc-drift-audit` 이었고, `doc_audit` 은 doc 유무를 개수로만 세 놓쳤다.

**쓰는 순간에 막아야 고치는 비용이 가장 작다.** 회차 끝에 잡으면 어느 커밋이 어느 doc 을 옮겼는지 되짚어야 한다. 사용자 지시(2026-11-13 「차단으로 올림」)로 비안전 차단을 들였다(`docs/harness-conventions.md` 「안전 임계 hook 의 차단 동작 변경」 ⑤). 판정은 주석 게이트 뒤에서 돌고, 라이브러리 로드 실패와 판정 예외는 모두 통과다(fail-open).

## §2 판정

**Edit·MultiEdit 만 본다.** 대상 확장자는 doc 예외와 같은 `.rs .cs .ts .tsx .js .jsx` 이다. 시스템 임시 폴더 아래 파일과 디스크에 없는 파일은 건너뛴다. 편집 전 내용은 디스크 파일이다(PreToolUse 라 아직 바뀌기 전). 편집 후 내용은 편집 쌍을 순서대로 적용해 만들고, `old_string` 을 하나라도 찾지 못하면 통과한다.

**doc 블록과 그 주인.** doc 블록은 `comment-lines.ps1` 의 `Get-CommentDocFlags` 가 doc 으로 표시한 연속 줄(`///`·`/** */`)이다. `//!` 로 시작하는 블록은 모듈 doc 이라 뺀다. 주인은 `Get-CommentDocTarget` 이 고른 블록 뒤 첫 코드 줄이다(빈 줄·속성은 건너뛴다).

**막는 조건 넷.** 편집 전에 한 번만 나오는 블록 B 의 주인이 X 였고, 편집 후에도 B 가 한 번만 나오며 그 주인이 Y(≠ X)이고, X 줄이 편집 후에도 파일에 남아 있고, B 의 어느 줄도 `old_string` 에 없으면 막는다. X 가 남아 있다는 것은 항목을 지우거나 이름을 바꾼 것이 아니라 그 앞에 무언가를 끼웠다는 뜻이다.

**바뀐 구간 ±80줄만 본다.** 파일 전체의 doc 블록마다 주인을 구하고 편집 후 줄을 집합에 담던 첫 판은 23,680줄 `.rs` 에서 hook 한 번이 약 1.4초 늘었다(BASE 593~608ms · HEAD 2024~2041ms). 남의 doc 을 빼앗을 수 있는 블록은 바뀐 줄 바로 앞뒤뿐이라 그 창만 본다. 바뀐 구간은 Edit 한 쌍이면 `old_string` 위치로, 그 밖은 공통 머리·꼬리 줄을 걷어 정한다. X 가 남았는지는 편집 후 텍스트의 부분 문자열로 본다. 이렇게 고친 뒤 교대 3쌍의 쌍 차 중앙값은 통과 꼴 +223ms · 끼우기 꼴 +149ms 이고, 대부분 첫 호출의 JIT 다.

## §3 예외와 한계

**`old_string` 에 doc 블록의 줄을 넣은 편집은 통과한다.** doc 을 일부러 다룬 편집으로 본다. 처방인 「앵커를 doc 블록의 첫 줄로」를 따르면 이 경로로 통과한다. 같은 편집을 다시 내도 통과하지 않는다.

**한계.** Write 로 파일 전체를 다시 쓰는 경우는 보지 않는다 — 의도한 doc 이동과 가를 예외 경계가 없고, 실해는 거의 Edit 였다. python 스크립트로 끼우는 경우는 `guard-bash` 의 `block-python-newcode`(`bash-guard-rationale.md` §22)가 새 코드 쓰기 자체를 막는다. 같은 문구의 doc 블록이 파일에 둘 이상이면 판정하지 않는다. 남의 doc 을 문장 중간에서 쪼개 새 항목이 그 doc 의 뒷부분을 물려받는 변종은 블록 문구가 바뀌어 잡지 못한다.
