# 새 주석 게이트 판정 근거

> `guard-harness.ps1` 이 dot-source 하는 편집 게이트(`guard-comment.ps1`)와 `guard-bash.ps1` 이 dot-source 하는 커밋 게이트(`guard-commit-comments.ps1`), 두 게이트가 함께 쓰는 판별 라이브러리(`comment-lines.ps1`)의 판정 근거다. 남겨도 되는 주석의 기준은 `skills/implement/references/code-style.md`「주석」 이 정본이고, 이 문서는 그 기준을 **언제·어떻게 강제하는가**만 다룬다.

## §1 왜 쓰는 순간을 막는가

**작성 기준은 첫 코드 task 전에 한 번 읽힐 뿐이라, 긴 회차에서는 주석을 쓰는 순간 그 기준이 곁에 없다.** 2026-10-31 Karina 레포 정리 커밋 `1035b54` 가 그 회차가 쓴 주석 91줄을 작성 위반으로 지웠고, 같은 함정이 그 레포 `docs/conventions.md` 에 이미 적혀 있었는데도 최소 세 번째 재발이었다. 그래서 2026-11-01 에 편집 직후 경고(옛 `post-write-checks` H4)를 들였다.

**경고는 대부분 무시됐다.** 2026-11-03 세션 전사 집계에서 경고 뒤 15개 레코드 안에 주석을 지우거나 언급한 경우가 15건, 아무 반응 없는 경우가 178건이었다(휴리스틱 판정). 같은 날 한 회차는 경고를 받은 직후 다음 명령으로 넘어갔고, 그 주석은 회차 끝 주석 정리(`skills/no-comments`)가 다시 지웠다. 경고는 `additionalContext` 에 붙을 뿐 다음 행동을 요구하지 않는다. **도구 호출이 실패로 돌아와야 다음 행동이 바뀐다** — 그래서 경고를 지우고 첫 시도 차단으로 바꿨다.

**판정은 하지 않는다.** 남겨도 되는 주석 다섯 중 기계로 가를 수 있는 것은 라이선스 고지와 린트·포매터 지시문뿐이다. 바꿀 수 없는 외부 제약·공개 API 계약 doc·이슈 링크와 프로젝트 규약이 요구하는 주석은 문맥을 읽어야 갈린다. 그래서 게이트는 첫 시도만 막고 예외 목록을 돌려준다. 예외에 들면 같은 편집·커밋을 다시 내 통과하고, 아니면 주석 없이 다시 쓴다. 최종 판정·삭제는 여전히 회차 끝 주석 정리가 맡는다.

**편집 게이트는 `guard-harness` 안에 둔다.** 처음에는 별도 PreToolUse hook 으로 만들었는데, Edit·Write 마다 pwsh 가 하나 더 떠 로컬 동시 실행 중앙값이 454~767ms 늘었다(교대 5회·10회). 사용자 답으로 같은 matcher 의 `guard-harness` 프로세스 안으로 합쳤고, 합친 뒤 추가 비용은 guard-harness 단독 기준 150ms 다(중앙값 777→927ms). 그 대가로 안전 임계 hook(`onFailure: block`) 안에 비안전 검사가 들어갔다. 그래서 판정은 `try` 안에서 돌고, 라이브러리 로드 실패·판정 예외·상태 폴더 쓰기 실패는 모두 통과다(fail-open). 시간 초과만은 `onFailure: block` 으로 막히므로 판정에 외부 호출(git)을 쓰지 않는다.

## §2 「새로 더한 주석」 판별

**Edit·MultiEdit 는 편집 쌍마다 `new_string` 의 주석 줄 중 같은 쌍의 `old_string` 에 (앞뒤 공백을 뺀 같은 줄로) 없는 것이다** — 옮기기만 한 주석과 손대지 않은 주석은 세지 않는다. Write 는 디스크의 지금 파일 내용을 `old_string` 으로 놓고 같은 규칙으로 잰다(새 파일이면 전체). PreToolUse 라 파일이 아직 바뀌기 전이어서 git 없이 이전 내용을 얻는다.

**주석 문법.** `//`·`/* */` 계열은 `.cs .ts .tsx .js .jsx .java .go .rs .cpp .c .h .hpp .fs .kt .swift`, `#` 계열은 `.py .ps1 .sh` 이고 `.ps1` 은 `<# #>` 블록도 본다. 블록 주석은 더한 텍스트 안에서 열림·닫힘을 따라가 블록 안 줄을 센다 — 따라가지 않으면 블록 밖에서 `*` 로 시작하는 코드 줄(포인터 역참조 등)을 주석으로 잘못 센다. doc 주석(`///`·`//!`·`/** */`)도 센다 — Karina 회차가 지운 주석의 절반 이상이 doc 주석이었다.

**세지 않는 줄.** 빈 주석 줄, shebang(`#!`), 그리고 주석 표지 **바로 뒤**가 린트·포매터 지시문(`eslint-`·`prettier-ignore`·`@ts-`·`noqa`·`NOLINT` 등)·`/// <reference`·인코딩 선언·`SPDX-License-Identifier`·`Copyright`·`@license` 인 줄이다. 접두 일치만 보는 이유는 「이 region 좌표는…」 처럼 본문 중간에 같은 낱말이 든 설명 주석까지 빠지지 않게 하려는 것이다. **영어 낱말과 겹치는 지시문은 언어별 원문 꼴로만 뺀다** — `//go:`(공백 없이)·`// #region`/`#endregion` 은 `//` 계열에서, `#Requires`·`#region`/`#endregion` 은 `.ps1` 에서만이다. 처음에는 `requires`·`region`·`go:` 를 언어와 무관한 본문 접두로 뺐는데, 완료 리뷰가 `.cs` 의 `// Requires admin rights …` 가 빠지는 것을 재현했다(골든 케이스 셋이 이 꼴을 잰다).

**보지 않는 것.** Python docstring(`"""…"""`)은 줄 단위로는 일반 문자열과 갈리지 않아 오탐이 나므로 세지 않는다. NotebookEdit 는 셀 소스의 전후를 얻을 입력이 없어 건너뛴다. 문서 파일(`*.md`)의 HTML 주석은 `code-style.md`「주석」 이 대상에서 뺐다. 시스템 임시 폴더 아래 파일(scratchpad 편집 스크립트 등)은 편집 게이트가 보지 않는다 — 그 스크립트의 문자열 속 주석을 막으면 오탐이고, 그 스크립트가 실제 파일에 쓴 주석은 커밋 게이트가 잡는다(2026-11-03 집계에서 편집 직후 경고의 대상이 scratchpad 스크립트인 경우가 이 레포 18건·Karina 레포 26건이었다).

## §3 재제출 키와 승인 목록

**재제출 키는 세션 + 범위 + 더한 주석 본문 집합(정렬)의 해시다** — 범위는 편집 게이트가 `edit|<정규화 경로>`, 커밋 게이트가 `commit|<커밋 레포>` 다. 첫 시도에 키 파일을 `~/.claude/.state/comment-gate/` 에 쓰고 막는다. 같은 키가 다시 오면 통과시킨다. 주석을 바꿔 다시 내면 집합이 달라 키가 달라지고 다시 막힌다. 다른 세션의 키는 쓰지 않는다 — 한 세션의 「남긴다」 판단이 다른 세션의 같은 주석을 통과시키지 않게 하려는 것이다.

**편집 게이트가 재제출로 통과시킨 주석 본문은 세션 단위 승인 목록에 적는다(경로 무관 — 본문만).** 커밋 게이트는 그 본문을 빼고 센다. 승인을 나누지 않으면 정당하게 남긴 주석이 커밋에서 한 번 더 막힌다.

## §4 커밋 게이트

**PreToolUse 는 명령이 돌기 전이라, 커밋이 실제로 담을 변경을 명령에서 다시 읽는다.** 경로를 주면(`-- <경로>`) 그 경로의 `git diff HEAD` 만 본다 — `git commit -- <경로>` 는 기본이 `--only` 라 다른 staged 변경을 담지 않고, 병행 세션 규약(`AGENTS.md`「병행 세션의 커밋」)이 이 꼴을 쓰므로, 합치면 다른 세션이 staged 한 주석으로 이 세션의 커밋이 막힌다. `-i`/`--include` 면 staged 도 합친다. 경로가 없으면 staged, `-a`/`--all` 이면 `git diff HEAD` 다. 같은 명령 안 앞선 `git add` 대상은 아직 staged 되지 않았으므로 따로 읽는다 — 추적 파일은 `git diff HEAD -- <파일>`, untracked 파일은 파일 전문이다.

**같은 커밋에서 지운 줄에 있던 주석 본문은 뺀다** — 주석을 다른 파일로 옮긴 커밋은 편집 게이트에서 통과한 이동이라, 커밋에서 다시 막으면 같은 이동이 두 번 막힌다.

**`MERGE_HEAD` 가 있는 커밋(충돌 해결 병합)은 검사하지 않는다** — 담기는 것은 상대 브랜치가 이미 자기 세션에서 거친 변경이고, 막으면 `karina:chain-plan` 코디네이터의 병합이 남의 주석으로 선다.

**수집 상한(파일 200 · 추가 줄 20000)을 넘으면 알리고 통과한다.** `guard-bash` 는 `onFailure: block`·timeout 60초라, 큰 diff 를 줄마다 판별하다 시간을 넘기면 Bash 호출이 통째로 막힌다. 코드 파일 200개×100줄 staged 커밋에서 BASE 대비 +1815ms(중앙값 2346→4161ms)를 쟀다. git 실패·레포 밖·상태 폴더 쓰기 실패도 통과다(fail-open).

**한계.** `--unified=0` diff 는 hunk 에 주변 줄이 없어, 기존 블록 주석(`/* … */`) 안에 더한 줄은 여는 표지를 보지 못해 주석으로 세지 못한다. 커밋 대상 수집(`-a`·경로·앞선 `git add`)은 `guard-commit-secrets.ps1` 과 따로 구현했다 — 수집 결과의 모양(파일별 `+`·`-` 줄 대 파일 구분 없는 추가 줄)이 달라 공용화하지 않았다.
