# 새 주석 게이트 판정 근거

> `guard-harness.ps1` 이 dot-source 하는 편집 게이트(`guard-comment.ps1`)와 `guard-bash.ps1` 이 dot-source 하는 커밋 게이트(`guard-commit-comments.ps1`), 두 게이트가 함께 쓰는 판별 라이브러리(`comment-lines.ps1`)의 판정 근거다. 남겨도 되는 주석의 기준은 `skills/implement/references/code-style.md`「주석」 이 정본이고, 이 문서는 그 기준을 **언제·어떻게 강제하는가**만 다룬다.

## §1 왜 쓰는 순간을 막는가

**작성 기준은 첫 코드 task 전에 한 번 읽힐 뿐이라, 긴 회차에서는 주석을 쓰는 순간 그 기준이 곁에 없다.** 2026-10-31 Karina 레포 정리 커밋 `1035b54` 가 그 회차가 쓴 주석 91줄을 작성 위반으로 지웠고, 같은 함정이 그 레포 `docs/conventions.md` 에 이미 적혀 있었는데도 최소 세 번째 재발이었다. 그래서 2026-11-01 에 편집 직후 경고(옛 `post-write-checks` H4)를 들였다.

**경고는 대부분 무시됐다.** 2026-11-03 세션 전사 집계에서 경고 뒤 15개 레코드 안에 주석을 지우거나 언급한 경우가 15건, 아무 반응 없는 경우가 178건이었다(휴리스틱 판정). 같은 날 한 회차는 경고를 받은 직후 다음 명령으로 넘어갔고, 그 주석은 회차 끝 주석 정리(`skills/no-comments`)가 다시 지웠다. 경고는 `additionalContext` 에 붙을 뿐 다음 행동을 요구하지 않는다. **도구 호출이 실패로 돌아와야 다음 행동이 바뀐다** — 그래서 경고를 지우고 첫 시도 차단으로 바꿨다.

**기계로 가를 수 없는 예외는 코드에 두지 않는다 — 게이트는 기계 판정 예외만 통과시키고, 같은 입력을 다시 내도 통과하지 않는다.** 2026-11-03 에 들인 첫 판은 「판정은 하지 않는다」 였다: 첫 시도만 막고 같은 편집·커밋을 다시 내면 통과시켰다. 다시 내는 데 근거가 필요 없어 규칙 밖 주석도 두 번째에 그대로 들어간다고 사용자가 지적했다(2026-11-04). 같은 기간 기록된 실제 재제출 2건(`hook-events` 2026-11-04 `agents.rs`·`queue_cards.rs`)은 둘 다 Karina 의 doc 감사(`AGENTS.md` `Test (감사)` — `pub` 항목에 doc 이 없으면 실패)가 요구한 계약 doc 이었다 — 정당한 재제출은 「프로젝트 규약이 요구하는 주석」 이었고, 그 규약은 `AGENTS.md` 줄이라 기계로 읽힌다. 그래서 문맥 판정을 재제출에 맡기지 않고 예외를 §3 의 기계 판정으로 바꿨다. 링크 없는 외부 제약은 커밋 본문으로 간다(`code-style.md`「주석」). 오탐으로 막히면 우회 변수 없이 멈추고 사용자에게 보고한다. 최종 판정·삭제는 여전히 회차 끝 주석 정리가 맡는다.

**편집 게이트는 `guard-harness` 안에 둔다.** 처음에는 별도 PreToolUse hook 으로 만들었는데, Edit·Write 마다 pwsh 가 하나 더 떠 로컬 동시 실행 중앙값이 454~767ms 늘었다(교대 5회·10회). 사용자 답으로 같은 matcher 의 `guard-harness` 프로세스 안으로 합쳤고, 합친 뒤 추가 비용은 guard-harness 단독 기준 150ms 다(중앙값 777→927ms). 그 대가로 안전 임계 hook(`onFailure: block`) 안에 비안전 검사가 들어갔다. 그래서 판정은 `try` 안에서 돌고, 라이브러리 로드 실패·판정 예외는 모두 통과다(fail-open). 시간 초과만은 `onFailure: block` 으로 막히므로 판정의 기본 경로에 외부 호출(git)을 쓰지 않는다 — 레포 루트·매니페스트·`AGENTS.md` 는 파일 시스템을 위로 올라가며 찾는다. 예외는 §3 「BASE 복원」 하나다: 차단 후보가 남은 파일에서만 `git show` 를 부르고, hook 호출 하나의 git 대기 시간 합에 예산(10초)을 걸어 바닥나면 예외 없이 막는다(`git show` 1회 217~449ms 실측 · 커밋 게이트는 파일 여럿이 한 예산을 나눠 쓴다). **예산은 git 을 기다린 시간만 깎는다** — 첫 판은 커밋 게이트 시작 때 벽시계 기한을 잡아, 앞 파일들의 판정 처리 시간이 기한을 먹었다. 2026-11-11 Karina plan 5 회차 끝 커밋이 2.3만·1.3만 줄 파일의 BASE 원문 복원 주석 90줄을 새 주석으로 막혔는데, 그 파일의 `git show` 는 55ms 였고 doc 대상 판정이 주석마다 파일 전체를 다시 훑어 주석당 약 185ms(주석 10개 1,845ms)를 썼다. doc 표시 배열은 이제 파일당 1회 만든다.

## §2 「새로 더한 주석」 판별

**Edit·MultiEdit 는 편집 쌍마다 `new_string` 의 주석 줄 중 같은 쌍의 `old_string` 에 (앞뒤 공백을 뺀 같은 줄로) 없는 것이다** — 옮기기만 한 주석과 손대지 않은 주석은 세지 않는다. **기존 주석의 문구 수정은 세지 않는다** — `old_string` 에서 사라진 주석 줄 수만큼은 새 주석이 아니라 고쳐 쓴 것으로 보고, 줄 수가 늘어난 만큼만 센다. 문구만 고쳐도 새 주석으로 세면 「낡은 doc 주석은 고친다」(`code-style.md`「주석」)가 막힌다. **고쳐 쓴 몫은 그 옛 주석과 가장 닮은 새 주석 줄에 배정한다** — 주석 표지를 뗀 본문의 문자 bigram Dice 계수로 모든 짝을 재고 큰 짝부터 겹치지 않게 고른다(같은 값·전부 0 이면 앞 줄). 순서대로 첫 새 주석에 몫을 쓰던 첫 판은, 같은 쌍에 새 주석(앞)과 문구 수정(뒤)이 함께 있으면 고친 줄을 새 주석으로 막았다(2026-11-10 Karina 커밋 · Write 재현). 문턱은 두지 않아 봐주는 줄 **수**는 그대로이고 **어느 줄**인가만 바뀐다 — 그래서 몫을 먹어 통과하던 예외 밖 새 주석이 이제 막히는 쪽으로도 판정이 움직인다(새 비공개 doc(앞) + pub 위 doc 문구 수정(뒤)). 새 주석 후보가 사라진 몫 이하면 전부 봐주므로 재지 않고, 짝 수(몫×후보)는 게이트 호출 하나에 2000짝 예산을 나눠 쓰며 넘는 쌍은 순서대로 소비한다 — 2000짝 배정이 중앙값 약 0.4초(2026-11-10 실측)라, 예산 없이 큰 재작성이나 hunk 가 많은 커밋을 재면 hook 시간 제한에 닿는다. 문구를 엉뚱하게 바꾸는 남용은 회차 끝 주석 정리가 맡는다. Write 는 디스크의 지금 파일 내용을 `old_string` 으로 놓고 같은 규칙으로 잰다(새 파일이면 전체). PreToolUse 라 파일이 아직 바뀌기 전이어서 git 없이 이전 내용을 얻는다.

**주석 문법.** `//`·`/* */` 계열은 `.cs .ts .tsx .js .jsx .java .go .rs .cpp .c .h .hpp .fs .kt .swift`, `#` 계열은 `.py .ps1 .psm1 .psd1 .sh .yaml .yml .toml` 이고 PowerShell 셋(`.ps1 .psm1 .psd1`)은 `<# #>` 블록도 본다. 설정 파일(`.yaml .yml .toml .psd1`)은 2026-11-05 에 더했다 — 그 전에는 이 확장자들의 주석 규칙이 문서로만 지켜졌다. 블록 주석은 더한 텍스트 안에서 열림·닫힘을 따라가 블록 안 줄을 센다 — 따라가지 않으면 블록 밖에서 `*` 로 시작하는 코드 줄(포인터 역참조 등)을 주석으로 잘못 센다. doc 주석(`///`·`//!`·`/** */`)도 센다 — Karina 회차가 지운 주석의 절반 이상이 doc 주석이었다.

**세지 않는 줄.** 빈 주석 줄, shebang(`#!`), 그리고 주석 표지 **바로 뒤**가 린트·포매터 지시문(`eslint-`·`prettier-ignore`·`@ts-`·`noqa`·`NOLINT` 등)·`/// <reference`·인코딩 선언·`SPDX-License-Identifier`·`Copyright`·`@license` 인 줄이다. 접두 일치만 보는 이유는 「이 region 좌표는…」 처럼 본문 중간에 같은 낱말이 든 설명 주석까지 빠지지 않게 하려는 것이다. **영어 낱말과 겹치는 지시문은 언어별 원문 꼴로만 뺀다** — `//go:`(공백 없이)·`// #region`/`#endregion` 은 `//` 계열에서, `#Requires`·`#region`/`#endregion` 은 PowerShell 셋에서만, YAML·TOML 도구 지시문(`# yamllint disable…`/`enable…`·`# yaml-language-server:`·`#cloud-config`·`#:schema`)은 `.yaml .yml .toml` 에서만이다. 처음에는 `requires`·`region`·`go:` 를 언어와 무관한 본문 접두로 뺐는데, 완료 리뷰가 `.cs` 의 `// Requires admin rights …` 가 빠지는 것을 재현했다(골든 케이스 셋이 이 꼴을 잰다).

**보지 않는 것.** Python docstring(`"""…"""`)은 줄 단위로는 일반 문자열과 갈리지 않아 오탐이 나므로 세지 않는다. NotebookEdit 는 셀 소스의 전후를 얻을 입력이 없어 건너뛴다. 문서 파일(`*.md`)의 HTML 주석은 `code-style.md`「주석」 이 대상에서 뺐다. 시스템 임시 폴더 아래 파일(scratchpad 편집 스크립트 등)은 편집 게이트가 보지 않는다 — 그 스크립트의 문자열 속 주석을 막으면 오탐이고, 그 스크립트가 실제 파일에 쓴 주석은 커밋 게이트가 잡는다(2026-11-03 집계에서 편집 직후 경고의 대상이 scratchpad 스크립트인 경우가 이 레포 18건·Karina 레포 26건이었다). **한계 둘** — YAML 블록 스칼라(`run: |` 등) 안에서 `#` 로 시작하는 줄도 주석으로 센다(들여쓰기를 따라가는 판별은 2026-11-05 사용자 답으로 들이지 않았다) · 생성 도구가 만든 템플릿 주석(`New-ModuleManifest` 의 `.psd1`·YAML 스캐폴드)을 그대로 커밋하면 막힌다(코드 확장자 스캐폴드와 같은 취급이다).

## §3 예외 판정 (기계 판정)

**두 게이트는 `comment-lines.ps1` 의 `Get-BlockedCommentBodies` 하나로 판정하고 상태 파일을 쓰지 않는다** — 같은 판정이 두 곳에 갈라지면 편집에서 통과한 주석이 커밋에서 막힌다. 순서대로 본다.

- **줄 예외** — `TODO`·`FIXME`·`XXX` 가 든 줄은 링크가 있어도 막는다. 링크는 줄 단위다: URL 은 `/issues/N`·`/pull/N`·`/-/issues/N`·`rfc-editor.org` 를 담을 때만(출처 URL 만 든 줄은 커밋 본문으로 — `code-style.md`「주석」) · `RFC NNNN` · `issue #N`·`PR #N`·`GH-N`·`이슈 #N`(`#` 필수 — 「이슈 2개」 가 걸리지 않게) · 트래커 키(대문자 둘 이상 + `-숫자`, `UTF-8`·`SHA-256`·`ISO-…` 같은 표준명 접두는 뺀다) · 파일 폴더나 레포 루트 기준으로 실재하는 `.md` 경로. `.rs` 는 `SAFETY:` 로 시작하는 줄도 통과다. 링크 한 줄이 같은 묶음의 다른 줄을 통과시키지 않는다. **한계** — 실재하는 경로만 붙이면 설명 주석도 통과한다(rationale 포인터를 살리려는 사용자 결정의 대가). 이 남용은 회차 끝 주석 정리가 잡는다.
- **보존 선언** — 레포 `AGENTS.md`(파일 폴더에서 레포 루트까지 처음 만난 것)의 `- **Comment (보존)**: \`정규식\` · 경로: \`pathspec …\`` 줄에 맞는 주석은 통과다. pathspec 은 그 `AGENTS.md` 폴더 기준 상대 경로나 파일 이름에 `-like` 로 맞춘다. 줄 형식 정본은 `skills/AGENTS-BOUNDARY.md` 다.
- **doc 묶음** — `///`·`//!`·`/** */` 줄은 연속한 doc 줄 뒤의 첫 코드 줄(빈 줄·속성 `#[`·`[`·`@` 은 건너뛴다)로 판정한다. ① 레포 `AGENTS.md` 의 `Test (감사)` 줄(파서는 `guard-task-audit.ps1` 의 `Get-TaskAuditRules`)의 `경로:` 에 파일이 맞고 그 `증가:` 정규식에 코드 줄이 맞으면 통과 ② 라이브러리 레포의 공개 항목이면 통과 — 라이브러리는 처음 만난 매니페스트로 가른다: `Cargo.toml` 은 (`[lib]` 또는 `src/lib.rs`) 이고 `publish = false` 가 없을 때, `*.csproj` 는 `OutputType` 이 `Exe`·`WinExe` 가 아니고 `IsPackable` 이 `false` 가 아닐 때, `package.json` 은 `"private": true` 가 없을 때. 공개 항목은 `.rs` `pub `(`pub(` 제외) · `.cs` `public `·`protected ` · TS/JS `export ` 다. 다른 언어의 doc 주석은 다른 예외가 없으면 막힌다.
- **BASE 복원** — 앞 예외를 다 지나고도 막힐 줄이 남으면, 파일 폴더에서 레포 루트까지 처음 만난 `plan.md` 의 `> BASE: <sha>` 커밋 시점 그 파일(`git show <sha>:<경로>`)의 주석 줄과 같은 줄(앞뒤 공백 뺀)은 통과다. 2026-11-04 Karina 체인 plan 12 는 T1 이 지운 비공개 `fn` doc 두 개(`doc-drift-audit` 이 유실로 셈)를 같은 회차에 BASE 원문 그대로 되살리려다 8회 막혔다 — 감사 대상이 아닌 doc 이라 다른 예외가 없었다. 완료 기록(`> 완료:`)이 있는 plan 의 BASE 도 쓴다 — 코디네이터 검증은 워커가 완료를 기록한 뒤 drift 를 찾아 복원을 지시한다. `plan.md`·BASE 부재, 자리표시 BASE, git 실패·예산 소진(git 대기 시간 합이 §1 의 예산을 넘은 것 — 판정 처리 시간은 세지 않는다), 조회 중 예외는 모두 예외 없음이다 — 예외를 더 주는 쪽의 실패를 통과로 두면 git 이 느릴 때 규칙 밖 주석이 전부 지나간다(§1 의 fail-open 은 판정 자체의 예외에만 쓴다). **한계** — 다음 계획이 `plan.md` 를 덮어쓸 때까지 끝난 회차의 BASE 로 예외가 걸리고, 같은 파일의 다른 위치로 옮긴 BASE 주석도 통과한다. 다음 회차가 앞 회차가 지운 doc 을 되살리는 편집은 새 BASE 에 그 줄이 없어 풀리지 않는다. 남용은 회차 끝 주석 정리가 잡는다.
- **레포 루트** 는 위로 올라가며 처음 만난 `.git`(폴더 또는 파일 — worktree) 의 폴더다. 없으면 파일 폴더만 본다.
- **편집 후 내용과 위치** — 다음 코드 줄은 편집 후 텍스트에서, 더한 주석의 **실제 위치**에서 읽는다. 같은 문구를 처음 나오는 줄로 찾으면 같은 문구가 파일에 이미 있을 때 엉뚱한 항목으로 판정한다(2026-11-04 v2.78.0 실해 — 오탐·미탐 둘 다). 더한 줄은 `Get-AddedCommentBodies` 가 쌍 안 줄 번호로 정하고, 편집 게이트는 그 줄에 표지를 달아 Edit·MultiEdit 를 디스크 내용에 순서대로 적용한 뒤 표지가 놓인 줄을 위치로 삼는다. `replace_all` 은 자리마다 판정해 하나라도 예외에 들지 않으면 막는다. Write 는 `content` 안 줄 번호다. 파일이 없거나 `old_string` 을 찾지 못하면 `new_string` 들만 이은 텍스트에서 같은 방식으로 읽고, 코드 줄이 없으면 doc 예외를 주지 않는다. 속성은 괄호(`[`·`(`)가 닫힐 때까지 건너뛴다 — 여러 줄 `#[derive(…)]` 의 이어진 줄을 코드 줄로 읽으면 감사 대상 doc 을 막는다.

## §4 커밋 게이트

**PreToolUse 는 명령이 돌기 전이라, 커밋이 실제로 담을 변경을 명령에서 다시 읽는다.** 경로를 주면(`-- <경로>`) 그 경로의 `git diff HEAD` 만 본다 — `git commit -- <경로>` 는 기본이 `--only` 라 다른 staged 변경을 담지 않고, 병행 세션 규약(`AGENTS.md`「병행 세션의 커밋」)이 이 꼴을 쓰므로, 합치면 다른 세션이 staged 한 주석으로 이 세션의 커밋이 막힌다. `-i`/`--include` 면 staged 도 합친다. 경로가 없으면 staged, `-a`/`--all` 이면 `git diff HEAD` 다. 같은 명령 안 앞선 `git add` 대상은 아직 staged 되지 않았으므로 따로 읽는다 — 추적 파일은 `git diff HEAD -- <파일>`, untracked 파일은 파일 전문이다.

**같은 커밋에서 지운 줄에 있던 주석 본문은 뺀다** — 주석을 다른 파일로 옮긴 커밋은 편집 게이트에서 통과한 이동이라, 커밋에서 다시 막으면 같은 이동이 두 번 막힌다. 파일 안에서는 §2 의 문구 수정 규칙을 **diff hunk 마다** 그 hunk 의 `-`·`+` 줄에 쓴다. BOM 이 붙은 첫 줄 머리 주석을 고친 커밋이 이 규칙 없이 막힌 실해가 있다(2026-11-04 이 회차 T1·T2 커밋). 첫 판은 파일 전체의 `-`·`+` 를 쌍 하나로 넘겨, 한 자리에서 지운 주석이 떨어진 다른 자리의 다른 새 주석을 문구 수정으로 봐줬다 — hunk 쌍으로 그 커밋은 이제 막힌다(2026-11-10). 같은 문구를 파일 안 다른 자리로 옮긴 것은 이 문단 첫 규칙(같은 커밋에서 지운 줄의 주석 본문은 뺀다)이 파일 전체에서 계속 빼 준다. 더한 줄 목록과 줄 번호는 파일 단위로 이어 두고 hunk 는 그 안의 시작 위치만 기록해, 쌍 안 줄 번호에 시작 위치를 더해 아래 위치 판정에 쓴다.

**doc 묶음의 다음 코드 줄은 커밋 대상 내용에서, hunk 줄 번호 위치로 읽는다** — `--unified=0` diff 에는 주변 줄이 없어 파일 내용이 필요하다. diff 를 모을 때 hunk 머리(`+c`)의 새 줄 번호와 출처를 함께 기록한다 — `--cached` 는 index(`git show :<경로>`), 경로·`-a`·같은 명령의 `git add` 대상은 작업 트리다. 같은 파일이 두 출처에서 오면(`-i`, `git add x && git commit`) 커밋에 담기는 작업 트리 쪽만 남긴다. 내용을 읽지 못하면 `+` 줄 목록 안 순번으로 판정한다. staged 와 작업 트리가 다른 커밋을 작업 트리로 판정하던 첫 판은 이 규칙으로 닫았다.

**`MERGE_HEAD` 가 있는 커밋(충돌 해결 병합)은 검사하지 않는다** — 담기는 것은 상대 브랜치가 이미 자기 세션에서 거친 변경이고, 막으면 `karina:chain-plan` 코디네이터의 병합이 남의 주석으로 선다.

**수집 상한(파일 200 · 추가 줄 20000)을 넘으면 알리고 통과한다.** `guard-bash` 는 `onFailure: block`·timeout 60초라, 큰 diff 를 줄마다 판별하다 시간을 넘기면 Bash 호출이 통째로 막힌다. 코드 파일 200개×100줄 staged 커밋에서 BASE 대비 +1815ms(중앙값 2346→4161ms)를 쟀다. git 실패·레포 밖도 통과다(fail-open).

**한계.** `--unified=0` diff 는 hunk 에 주변 줄이 없어, 기존 블록 주석(`/* … */`) 안에 더한 줄은 여는 표지를 보지 못해 주석으로 세지 못한다. 커밋 대상 수집(`-a`·경로·앞선 `git add`)은 `guard-commit-secrets.ps1` 과 따로 구현했다 — 수집 결과의 모양(파일별 `+`·`-` 줄 대 파일 구분 없는 추가 줄)이 달라 공용화하지 않았다.
