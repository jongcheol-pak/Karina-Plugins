- [2026-10-27] 주석 정리 스킬의 실행 경로 — **번복**: 2026-10-23 의 「사용자 호출 전용 · 남은 결함은 스킬 안에서 설계를 승인받아 고친다」 를 버리고, `karina:implement` 가 회차 끝 마지막 전체 검증 앞에서 주석을 쓰지 않은 리뷰어로 주석 정리를 1회 돌린다. 범위 안 MUST KILL 은 승인 없이 고치고, 승인은 제약 주석을 코드로 옮길 때만 받는다(직접 호출도 같다). pstack 원문 「리뷰 전에 no-comments 를 돈다 · 주석을 쓴 쪽이 아닌 쪽이 판정한다」 에 맞추려는 사용자 요청이다.
  - 함께 해제한 2026-10-17 주석 규칙 회차의 제약: 「문서 규칙만 둔다」·「MUST KILL 지목을 implement 에 들이지 않는다」.
  - 재실행 방지는 plan Progress Log 의 `주석 정리:` 표지 한 줄이 맡는다 — 재개·검증 재실행·리뷰 수정 루프에서 다시 돌지 않게 해 달라는 사용자 지시다. 범위는 그 plan 의 커밋뿐이고, 경량 plan 의 작은 회차는 리뷰어 대신 세션이 판정한다.
- [2026-10-27] 주석 자동 정리를 디버깅 단독 경로와 완료 리뷰어 대조에도 두는 안 — **기각**: 자동 실행은 implement 회차 끝 하나다(사용자 답). 완료 리뷰어에 주석 대조를 더하면 자동 모드와 같은 검사가 두 번 돈다.
- [2026-10-27] 완료 보고의 요구 항목별 결과 줄 · 성능 측정 전 기계 부하 확인 — **보류**: 「확인할 파일」 회차의 후보였으나 사용자가 보류했다. 앞의 것은 Deferred 대장에 올렸다.
- [2026-10-26] 차단 hook 의 공백 경로 `git -C … push --force` 미탐 가능성 — **보류**: 계획 체인 스택 회차에서 실해가 관측되지 않아 사용자가 보류했다.
- [2026-10-25] 우회 금지 규칙을 hook 차단 메시지 문구와 세션 시작 주입으로도 알리는 안 — **보류**: 지침 문서만 바꿨다. 안전 임계 hook 의 문구 변경과 주입 예산 비용 때문에 사용자가 보류했다.
- [2026-10-24] 사용자 보고 언어 리마인더를 bash `echo` 로 내 기동 시간을 줄이는 안 — **기각**: 리마인더 문구가 PowerShell hook 과 두 곳으로 갈라진다. 사용자 턴마다 pwsh 기동 시간이 더해지는 비용은 감수한다.
- [2026-10-24] worktree 정리 백업에서 뺄 ignore 폴더 — **채택**: 잘 알려진 빌드·캐시 폴더 이름 목록은 크기와 무관하게 건너뛰고, 목록 밖 ignore 폴더는 기존 크기 상한을 유지한다. 목록 밖 산출물은 상한이 걸러 낸다(사용자 선택).
  - 기각한 대안: ignore 폴더 전부 제외 — 단순하지만 사람이 만든 ignore 폴더(노트 아카이브 등)도 백업되지 않는다.
- [2026-10-24] 버전 올리기 경로 — **번복**: 회차 PR 을 merge 할 때마다 버전 전용 PR 을 새로 열던 방식을 버리고, ship 이 merge 직후 최신 base 위에 버전만 올린 커밋을 바로 push 한다. 버전 PR 이 CI·merge 전 검증을 한 바퀴 더 돌았기 때문이다. 버전 커밋은 PR·검증자를 거치지 않고 push 전 변경 파일 집합 확인으로 갈음한다.
  - 기각한 대안: merge 직전에 PR 에 버전 커밋을 얹는 안 — PR 이 갈라진 뒤 다른 PR 이 버전을 올리면 같은 버전 줄이 squash 에서 충돌한다.
  - 바뀌지 않은 것: PR 모드가 꺼진 회차의 로컬 버전 커밋 경로 · 릴리즈 발행은 별도 승인 · push 뒤 base CI 를 기다리지 않는다.
