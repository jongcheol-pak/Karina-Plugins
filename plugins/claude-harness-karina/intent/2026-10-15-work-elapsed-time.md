# Intent: plan·체인 완료 보고에 시작·완료 시각과 소요 시간을 싣는다
Author: 사용자(jongcheol-pak). Status: approved.

## Problem
계획을 세우고 구현을 마쳐도 그 작업이 언제 시작돼 얼마나 걸렸는지가 어디에도 남지 않는다 — `plan.md` 에는 승인 날짜(`> 승인: YYYY-MM-DD`)만 있고 시각은 없다. 사용자 요청: 「plan/chain-plan에서 작업 완료시 작업을 시작한 시간과 완료 시간을 plan.md 파일에 저장해 놨다가 작업 완료시 시작시간/완료시간/작업한 시간을 표시해 줄 수 있나?」

원문:
- Q: 「시작」을 어디로 잡을까 — implement 착수 / plan 승인 / plan 인터뷰 착수 · 세션 공백을 뺄까 — A: 「인터뷰 부터, 단순 시작~완료 / 소요 시간으로 계획 세워줘」
- Q: 체인 보고에 무엇을 싣는가 — 선택지: 체인 전체 + 계획별 워커 시간 (권장) / 체인 전체만 / 계획별로도 인터뷰 착수부터 — A: 「체인 전체 + 계획별 워커 시간」
- Q: 토큰 비용 — A(설계 답): 별도 왕복을 만들지 않고 이미 있는 명령·편집에 얹는 방식 — 「응, 그 방식으로 진행해」
- 후보 라운드(정합 검사기 슬롯 등록 · plan 작성 전 압축 시 시작 시각 유실 · 실패 워커 소요) — A: 「응, 권장대로 진행해」(셋 다 제외)

## Proposed outcome
단독 plan 은 `pjc:plan` 이 시작할 때 잰 시각을 `plan.md` `## Goal` 의 `> 시작:` 줄에 적고, `pjc:implement` 가 끝날 때 `> 완료:` 줄을 적은 뒤 완료 보고에 `시작 ~ 완료 (소요)` 한 줄을 낸다. 소요는 단순 차(세션 공백 포함)다. 체인은 코디네이터가 첫 인터뷰 착수 시각과 체인 끝 시각으로 전체 소요를, 워커 `--body` 의 소요 필드로 계획별(워커 시작~완료) 소요를 체인 보고에 싣는다. 시각은 셸 출력에서만 오고, 기록은 이미 있는 셸 호출·편집에 얹어 별도 왕복을 늘리지 않는다.

## Affected users and systems
pjc 하니스로 plan·체인을 돌리는 사용자 · `pjc:plan`(Step 1·Step 5) · `pjc:implement`(완료 순서·최종 보고) · `pjc:chain-plan`(인터뷰·Run objective·워커 보고 필드·체인 보고·압축 복원) · README.

## Constraints
시각은 모델이 짐작하지 않고 셸 출력만 쓴다. `> 승인:` 판정 정규식(`^> 승인: [0-9]{4}-`)과 `> BASE:` 줄은 건드리지 않는다. 구현 재개·초안 이어 쓰기에서 `> 시작:` 을 덮어쓰지 않는다. `> 시작:` 이 없는 옛 plan 은 「시작 미기록」으로 표시한다. `SKILL.md` 상한(12,000자)을 넘기지 않는다.
